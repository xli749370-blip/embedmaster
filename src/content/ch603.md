# 第三章 底层驱动开发：让硬件真正动起来

> 板子焊好了，但它还是一块"沉默的石头"。驱动层就是告诉 MCU 怎么跟每个器件对话。本章全部以 STM32 外设 + 嵌入式 C 写法展开。

## 3.1 目录分层：不要所有代码塞 main.c

沿用模块化课的"单向依赖"原则：

```
bsp/       板级支持：时钟、GPIO、滴答
drv/       器件驱动：sht30.c / ble.c / led.c
hal/       MCU 外设封装（或直接用 HAL 库）
app/       业务：采集、上报、状态机
main.c     只做初始化与启动调度
```

- `drv/sht30.c` 只依赖 `hal_i2c`，不碰业务。
- `app/` 调用驱动，不知道 SHT30 寄存器细节。
- 好处：换芯片只改 `hal/`；换传感器只改 `drv/`。

## 3.2 I2C 读 SHT30

SHT30 地址 `0x44`（ADDR 引脚接地），读一次测量值的流程：

1. 发送测量命令：`0x2C 0x06`（高速、时钟延展禁止）
2. 等待 ≥ 12 ms（测量完成）
3. 读 6 字节：`[温度高][温度低][T_CRC][湿度高][湿度低][H_CRC]`

温度换算：

$$T = -45 + 175 \times \frac{S_T}{65535} \quad [{}^\circ\text{C}]$$

湿度换算：

$$RH = -6 + 125 \times \frac{S_{RH}}{65535} \quad [\%RH]$$

> 坑点：SHT30 返回的是**原始 16 位无符号数**，必须按上面公式线性映射，不能直接当浮点温度。CRC 校验失败的数据应当丢弃并补测。

## 3.3 ADC 读电池电压

电池经 $R_a=R_b=100\,\text{k}\Omega$ 分压，ADC 看到的是真实电压的一半。设参考电压 $V_{ref}=3.3\,\text{V}$、12 位分辨率：

$$V_{bat} = 2 \times V_{ref} \times \frac{RAW}{4095}$$

工程上要做的三件事：

1. **多次采样平均**：采样 16 次取均值，抑制噪声。
2. **软件滤波**：去掉最大最小后平均，挡掉偶发尖峰。
3. **低电判断**：阈值设 3.4 V（满电 4.2 V），低于则亮 LED 提示。

## 3.4 PWM 控制呼吸灯

用定时器通道输出 PWM 驱动 LED。占空比 $d$ 从 0 渐变到 100 再回落，就是"呼吸"：

$$d(t) = \frac{1 - \cos(2\pi f_{breath} t)}{2} \times 100\%$$

- 频率用 1 kHz（肉眼不闪），呼吸周期用 2 s（慢一点更柔和）。
- 低电量时改快速闪烁：固定 50% 占空比、2 Hz。

> 直接用 `TIMx->CCRy` 改比较值即可，无需每周期重配定时器。配合 RTOS 用一个低速任务更新占空比。

## 3.5 UART 与蓝牙模块

蓝牙模块上电即进入透传，MCU 通过 UART 发什么，手机就收到什么。初始化步骤：

1. 配置 UART（波特率 9600 或 115200，模块默认常是 9600）。
2. 上电后可发 AT 指令设名字/波特率（仅配置期，平时不发了）。
3. 业务数据直接 `HAL_UART_Transmit` 丢出去即可。

一个稳健的发送写法：

```c
void ble_send(const uint8_t *buf, uint16_t len) {
    // 阻塞发送，简单可靠；后续可改 DMA + 空闲中断提升效率
    HAL_UART_Transmit(&huart2, (uint8_t *)buf, len, HAL_MAX_DELAY);
}
```

## 3.6 驱动的"可测试性"

每块驱动都应能在**不依赖整机**的前提下验证：

| 驱动 | 最小验证 | 通过标准 |
| --- | --- | --- |
| I2C/SHT30 | 串口打印温湿度 | 室温下 20~30 ℃、40~60 %RH |
| ADC | 串口打印分压读数 | 接 3.3 V 读 ~3.3 V |
| PWM | 肉眼看 LED 呼吸 | 平滑渐变无突跳 |
| UART | 手机收到字符串 | 透传内容一致 |

> 经验：每写完一个 `drv/`，立刻写一段 `app_test_xxx()` 验证，验证通过再删掉或保留为注释。这样出问题时能快速锁定是硬件还是软件。

## 3.7 常见驱动坑

1. **I2C 地址左移**：HAL 的 `HAL_I2C_Mem_Write` 要求地址已含读写位（即 `0x44<<1`），直接传 `0x44` 会 NACK。
2. **ADC 未校准**：上电先 `HAL_ADCEx_Calibration_Start`，否则读数系统性偏移。
3. **UART 阻塞太久**：`HAL_MAX_DELAY` 在中断里调用会卡死系统，RTOS 下要换非阻塞。
4. **浮点运算耗电**：低端 MCU 做除法/浮点慢且费电，能用定点（×100 整数）就用定点。

## 本章要点

- 目录分层：bsp / drv / hal / app，单向依赖
- SHT30：命令 0x2C06 → 读 6 字节 → 线性公式换算 → 校验 CRC
- 电池电压 = 2 × 3.3 × RAW / 4095，需平均与滤波
- PWM 呼吸用余弦占空比，低电量改快闪
- UART 透传：直接发，先 AT 配置后业务
- 每块驱动都要能独立验证；注意 I2C 地址左移、ADC 校准
