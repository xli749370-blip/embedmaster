# 第六章 I2C 与 SPI：和外围器件说话

> 前面的 GPIO、定时器、ADC 都是芯片"自己"的能力。真正让系统变大的，是挂上去的那一堆器件：温湿度传感器、EEPROM、OLED 屏、陀螺仪、SD 卡。它们绝大多数只认两条总线——I2C 或 SPI。选错了、配错了，表现都是"读不到数据"。

## 6.1 I2C：两根线挂一串器件

I2C 全称 Inter-Integrated Circuit，只用两根线：

| 线 | 全称 | 作用 |
|---|---|---|
| SCL | Serial Clock | 时钟，由主机产生 |
| SDA | Serial Data | 双向数据线 |

**关键特性：两根线都是开漏输出 + 外部上拉电阻。** 这不是设计者的随意选择，而是整个协议能工作的前提。

开漏意味着任何器件只能把线**拉低**，不能主动拉高——高电平靠上拉电阻。于是所有器件并联在一起时：

- 所有器件都不拉 → 线上是高（空闲）
- 任何一个器件拉低 → 线上是低

这叫**线与（wired-AND）**。它天然实现了三个功能：多主机仲裁（谁拉低谁赢）、时钟拉伸（从机跟不上就把 SCL 拉低）、总线冲突检测。如果用推挽输出，两个器件一个想拉高一个想拉低，就是电源直接短路。

### 传输时序

一次完整的写操作：

```
    ┌── 起始 ──┐                                    ┌── 停止 ──
SCL ┘▔▔▔▔▔▔▔▔▔█████████████████████████████████████▔▔▔▔▔▔▔▔▔▔▔
SDA ▔▔▔▔▔┐  地址(7位)  ┐ R/W ┐  ACK ┐  数据(8位)  ┐ ACK ┐▔▔▔▔▔▔▔
         └─────────────┴─────┴──────┴─────────────┴─────┘
```

- **起始条件（START）**：SCL 为高时，SDA 由高变低
- **停止条件（STOP）**：SCL 为高时，SDA 由低变高
- **地址**：7 位，紧跟 1 位读写标志（0 写 / 1 读）
- **ACK**：接收方把 SDA 拉低一个时钟，表示"收到了"

**起始和停止都是在 SCL 高电平期间改变 SDA**，这是唯一允许 SDA 在高电平期间变化的时刻。其余时间 SDA 必须在 SCL 低电平期间改变，否则会被误判为起始/停止。

**时序图最好能自己"走一遍"。** 下面这个动画把 I²C 与 SPI 放进同一个交互面板：I²C 看 SCL/SDA 如何用 9 拍完成"地址 + ACK"和"数据 + ACK"，SPI 看 CS 拉低后 8 个时钟如何把一字节 MSB 先发出去。切换模式对比着看，两种总线的差别就很直观了。

### 器件地址

7 位地址意味着理论上 128 个地址，其中 0x00–0x07 和 0x78–0x7F 保留，实际可用约 112 个。常见器件：

| 器件 | 7 位地址 | 说明 |
|---|---|---|
| SSD1306 OLED | 0x3C 或 0x3D | 取决于模块的 D/C 电阻 |
| MPU6050 陀螺仪 | 0x68 或 0x69 | 由 AD0 引脚决定 |
| AT24C02 EEPROM | 0x50–0x57 | 低 3 位由 A0–A2 引脚决定 |
| BMP280 气压计 | 0x76 或 0x77 | 由 SDO 引脚决定 |
| PCF8574 IO 扩展 | 0x20–0x27 | 可挂 8 片 |

**这里有个极易混淆的坑：数据手册里的地址到底是 7 位还是 8 位？**

- 有些手册写 `0x78`（这是把读写位算进去的 8 位形式）
- 有些写 `0x3C`（7 位形式）
- HAL 库的 `HAL_I2C_Master_Transmit` 要求传入**左移后的 8 位地址**（即 `0x3C << 1 = 0x78`）

所以看到 OLED 模块说地址是 0x78，实际传给 HAL 的也是 0x78；如果说地址是 0x3C，那要左移一位。**搞不清就两个都试一遍，用 I2C 扫描程序一次性列出总线上所有器件，这是最省时间的做法。**

### 上拉电阻怎么选

上拉电阻和总线电容构成 RC 电路，上升时间必须小于规范值：

$$
t_r \le 0.8473 \times R_{pull} \times C_{bus}
$$

标准模式（100kHz）允许 $t_r \le 1000\text{ns}$，快速模式（400kHz）允许 $t_r \le 300\text{ns}$。

工程经验值：

| 场景 | 推荐上拉 |
|---|---|
| 100kHz，短走线（< 10cm） | 10 kΩ |
| 400kHz，短走线 | 4.7 kΩ |
| 400kHz，多器件长走线 | 2.2 kΩ |
| 1.7MHz 以上 | 1 kΩ 以下 |

**注意矛盾点：上拉越小，上升越快，但静态功耗越大。** 因为总线空闲时（高电平），每个器件都在通过上拉电阻灌电流。3.3V / 4.7kΩ ≈ 0.7mA，看着不大，但电池供电设备要算进去。

**很多模块已经自带上拉电阻（通常是 4.7kΩ 或 10kΩ）**。挂多个模块时，上拉电阻是并联的，等效阻值变小。挂 5 个 4.7kΩ 模块，等效上拉变成 0.94kΩ，电流达到 3.5mA——如果模块本身驱动能力不够，可能出现逻辑误判。这时应该去掉部分模块上的上拉。

## 6.2 SPI：四根线换来速度

SPI 全称 Serial Peripheral Interface，四根线：

| 线 | 作用 |
|---|---|
| SCK | 时钟，主机产生 |
| MOSI | Master Out Slave In，主机发 |
| MISO | Master In Slave Out，从机发 |
| CS / NSS | 片选，低电平选中，每个从机一根 |

**SPI 是全双工的**：发一个字节的同时就收到一个字节，这两个动作在同一个时钟周期内完成。这是它比 I2C 快得多的根本原因——I2C 是半双工，发和收必须分时。

**推挽输出，无上拉。** SPI 的线是推挽驱动，速度可以做到几 MHz 到几十 MHz，代价是每个从机要独占一根 CS 线（I2C 用地址寻址，不需要额外的线）。

### 四种模式：CPOL 与 CPHA

这是 SPI 最容易出错的配置。两个参数各两种取值，组合成四种模式：

- **CPOL（Clock Polarity）**：空闲时 SCK 是高还是低。0 = 空闲低，1 = 空闲高。
- **CPHA（Clock Phase）**：在第几个边沿采样。0 = 第一个边沿（上升沿或下降沿，取决于 CPOL），1 = 第二个边沿。

| 模式 | CPOL | CPHA | 空闲电平 | 采样边沿 |
|---|---|---|---|---|
| Mode 0 | 0 | 0 | 低 | 上升沿 |
| Mode 1 | 0 | 1 | 低 | 下降沿 |
| Mode 2 | 1 | 0 | 高 | 下降沿 |
| Mode 3 | 1 | 1 | 高 | 上升沿 |

**怎么知道用哪个模式？查器件手册。** 手册里一般写"支持 SPI Mode 0 和 Mode 3"，或者在时序图里标出 CPOL/CPHA。

**配错模式的表现**：读到的数据全是 0x00 或 0xFF，或者高位和低位错位（比如期望 0x12 读到 0x24，即左移了一位）。高位错位是"采样边沿偏了半拍"的典型症状。

```c
hspi1.Init.CLKPolarity = SPI_POLARITY_LOW;    /* CPOL = 0 */
hspi1.Init.CLKPhase    = SPI_PHASE_1EDGE;     /* CPHA = 0 → Mode 0 */
hspi1.Init.BaudRatePrescaler = SPI_BAUDRATEPRESCALER_8;  /* 72MHz/8 = 9MHz */
hspi1.Init.FirstBit = SPI_FIRSTBIT_MSB;       /* 绝大多数器件是 MSB 先行 */
```

**`FirstBit` 也常配错。** 99% 的器件是 MSB 先行，但少数（如某些 DAC、老式 ADC）是 LSB 先行。配错的表现是数据位完全颠倒。

### 速度上限怎么看

SPI 的理论速率由 SCK 频率决定，但实际受三个因素限制：

1. **器件规格**：SD 卡初始化阶段只能跑 400kHz，识别完成后才能上到 25MHz
2. **走线长度**：超过 10cm 的高速 SPI 会有反射和串扰，需要串阻或降速
3. **主机分频**：STM32 的 SPI 时钟来自 APB 总线，只能整数分频（2/4/8/.../256），不能任意设

所以"我要 10MHz"这种需求，实际只能取到最接近的分频档。

### 高速读数据：为什么必须是「收发同时」

很多人第一次读 SPI Flash 是这样写的：

```c
uint8_t cmd[4] = {0x03, 0x00, 0x12, 0x34};
uint8_t buf[8];
HAL_SPI_Transmit(&hspi1, cmd, 4, 100);     /* 先发命令 */
HAL_SPI_Receive(&hspi1, buf, 8, 100);      /* 再收数据 —— 错！ */
```

这段代码在逻辑分析仪上会看到：发命令的那 4 个字节期间，SCK 照样在打，MISO 上从机已经在往外吐数据了，而 CPU 根本没去读 `DR`。等 `HAL_SPI_Transmit` 返回、再调用 `HAL_SPI_Receive` 时，从机早就把这几个字节发完了——**读到的数据永远整体错位**。

原因是 SPI 是**全双工**的：时钟只要在走，收和发就同时发生，不存在「只发不收」这个动作。所谓「只发」，本质是把收到的字节丢掉。

正解是把收发合成一次调用：

```c
uint8_t cmd[8] = {0x03, 0x00, 0x12, 0x34, 0xFF, 0xFF, 0xFF, 0xFF};
uint8_t rx[8];
/* TX 与 RX 各挂一条 DMA 通道，8 个字节在同一个节拍里换完 */
HAL_SPI_TransmitReceive_DMA(&hspi1, cmd, rx, 8);
```

注意 `cmd` 数组的长度：命令 + 3 字节地址 + **4 字节 dummy**。这 4 个 dummy 不是废话，它们的唯一作用是「把时钟打出来」，让从机有机会把数据吐在 MISO 上。dummy 的**个数**取决于器件手册——少写一个，数据就整体左移一个字节，而现象和「SPI 模式配错」一模一样。

[[anim:spi-dma]]

看动画时注意两件事：① TX 与 RX 两行是**同拍**推进的，不存在先后；② RX 前 6 格是灰色的——那正是命令与地址阶段 MISO 上的无效数据，真正的数据从第 7 格才开始。搞不清这一点，就会把「数据错位」误判成「CPOL/CPHA 配错」，然后在四种模式里反复试，浪费一整天。

## 6.3 两者怎么选

| 维度 | I2C | SPI |
|---|---|---|
| 线数 | 2（SCL、SDA） | 4 + 每个从机 1 根 CS |
| 双工 | 半双工 | 全双工 |
| 速率 | 100k / 400k / 3.4M | 几 M ~ 几十 M |
| 寻址 | 7 位地址，软件寻址 | 硬件片选 |
| 多器件 | 挂同一条线，省引脚 | 每片独占 CS，费引脚 |
| 上拉 | 必需 | 不需要 |
| 抗干扰 | 较弱（开漏、上拉弱） | 较强（推挽） |
| 典型器件 | 传感器、EEPROM、OLED | 屏幕、Flash、SD 卡、无线模块 |

**选择原则：**

- **要省引脚、器件多、速率低** → I2C
- **要高速、要全双工、要可靠** → SPI
- **器件本身只支持一种** → 没得选

特别提一下 **I2C 的可靠性短板**：开漏 + 上拉意味着信号边沿缓慢、抗干扰弱，长距离传输容易出错。如果你的传感器在电机旁边、走线超过 20cm，I2C 会频繁报错。这时要么改成 SPI，要么用 I2C 隔离器/缓冲器。

## 6.4 总线死锁：I2C 特有的故障

这是 I2C 最让人头疼的问题，现象是：**程序卡在等待 ACK，或者 SCL 一直被拉低，重启才好。**

**成因**：主机在从机正在发数据时复位了。从机还停留在"我要发下一个 bit"的状态，把 SDA 拉低等待时钟；而主机复位后认为总线空闲，发出 START 条件——但因为 SDA 被从机拉着，这个 START 无效，双方僵持。

**恢复方法**：手动在 SCL 上打 9 个时钟脉冲，让从机把剩下的 bit 发完，然后发一个 STOP 条件。

```c
void I2C_Bus_Recover(void)
{
    /* 先把引脚切成普通 GPIO 推挽输出 */
    GPIO_InitTypeDef g = {0};
    g.Pin = GPIO_PIN_6 | GPIO_PIN_7;
    g.Mode = GPIO_MODE_OUTPUT_OD;
    g.Pull = GPIO_PULLUP;
    g.Speed = GPIO_SPEED_FREQ_HIGH;
    HAL_GPIO_Init(GPIOB, &g);

    /* 打 9 个时钟 */
    for (int i = 0; i < 9; i++) {
        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_RESET);
        HAL_Delay(1);
        HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET);
        HAL_Delay(1);
    }

    /* 发 STOP 条件：SCL 高时 SDA 低→高 */
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_7, GPIO_PIN_RESET);
    HAL_Delay(1);
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_6, GPIO_PIN_SET);
    HAL_Delay(1);
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_7, GPIO_PIN_SET);
    HAL_Delay(1);

    /* 重新初始化 I2C 外设 */
    MX_I2C1_Init();
}
```

成熟的工程会把这个恢复函数挂在 I2C 错误回调里，自动执行。**没有任何 I2C 项目应该省略这个函数**——它决定了设备是"偶发需要重启"还是"能自愈"。

## 6.5 六个配置陷阱

**陷阱一：I2C 引脚配成推挽。**
必须是**开漏复用**（`GPIO_MODE_AF_OD`）。配成推挽后，两个器件同时拉会短路，轻则通信失败，重则烧引脚。

**陷阱二：忘记外部上拉。**
很多开发板的 I2C 引脚内部上拉只有 30–50kΩ，配上 400kHz 速率根本拉不起来（上升沿太慢），波形变成圆角，采样失败。必须外接 4.7kΩ。

**陷阱三：SPI 从机的 CS 忘记拉低。**
CS 不拉低，从机根本不响应，MISO 保持高阻态，读回来全是 0xFF。用软件控制 CS 时，拉低 → 传输 → 拉高 三步缺一不可。

**陷阱四：SPI 多从机共享时钟但 CS 时序重叠。**
两个从机的 CS 同时有效，它们会同时驱动 MISO，造成总线冲突。切换从机时要保证"先拉高旧的 CS，再拉低新的 CS"，中间加一点延时。

**陷阱五：I2C 地址左移搞错。**
如前所述，HAL 要求传入左移后的地址。用扫描程序先确认实际地址，比猜要快得多。

**陷阱六：EEPROM 写入后立刻读。**
AT24Cxx 系列在写周期内（约 5ms）不响应任何命令。写完必须延时或者用 ACK 轮询等待，否则紧接着的读操作会 NACK 失败。

## 6.6 本章小结

- I2C 靠开漏 + 上拉实现线与，这是多器件、仲裁、时钟拉伸的基础；必须配开漏。
- 地址有 7 位和 8 位两种写法，HAL 要 8 位（左移后），不确定就扫描总线。
- 上拉电阻按速率和总线电容选，多模块并联会降低等效阻值。
- SPI 全双工、推挽、高速，代价是每个从机一根 CS。
- CPOL/CPHA 组合成四种模式，配错表现为全 0、全 FF 或数据错位。
- I2C 总线死锁可用"9 个时钟 + STOP"恢复，成熟工程应自动执行。
- 六个陷阱：推挽配 I2C、漏上拉、CS 没拉低、CS 重叠、地址没左移、EEPROM 写周期。

## 结语：这条链上还缺一环

这六章串起来是一条完整的链：

**GPIO** 让你控制引脚 → **中断**让你及时响应 → **定时器**让你产生精确的时间与波形 → **ADC** 让你感知模拟世界 → **串口**让你看见内部状态 → **总线**让你接入更多器件。

不过这条链上还缺最关键的一环：**这些数据到底是怎么高效地进到内存里的？** 到目前为止，每一次读 ADC、每一次收串口，都是 CPU 亲自一趟一趟搬。采样率一上 10 kHz，CPU 就什么别的都干不了，波形还会断断续续。

下一章把 DMA 这条旁路通道彻底讲透：单缓冲为什么必然串行、双缓冲（乒乓）怎么绕开这个死结、半传输中断又帮你省下了多少延迟。
