# 第四章 ADC：把模拟世界读进数字域

> 上一章的 PWM 是"数字变模拟"——用开关等效出中间电压。ADC 是相反方向：把连续变化的电压切成一格一格的数字。这个"切"的动作里藏着分辨率、采样时间、参考电压三个互相牵制的参数，配错任何一个，读出来的值都会漂。

## 4.1 分辨率：一个 LSB 值多少电压

STM32 的 ADC 是 12 位，输出范围 0–4095，共 4096 个刻度。最小可分辨的电压变化叫 **1 LSB**：

$$
1\ \text{LSB} = \frac{V_{ref}}{2^{12}} = \frac{3.3\text{V}}{4096} \approx 0.806\ \text{mV}
$$

换算公式：

$$
V_{in} = \frac{\text{ADC\_Value}}{4095} \times V_{ref}
$$

或者更精确地用 4096：

$$
V_{in} = \frac{\text{ADC\_Value} + 0.5}{4096} \times V_{ref}
$$

后一个公式体现了"量化"的本质：ADC 输出的每个码代表的是一个区间（比如码值 100 代表 100.5 LSB 附近 ±0.5 LSB 的范围），而不是一个精确点。取区间中点更接近真实值。

**0.806mV 这个数字要记住。** 它决定了你能测到多细的变化：

- 测 5V 需要分压到 3.3V 以内，分压后精度损失同样比例
- 测 NTC 热敏电阻，在常温区每 1℃ 变化可能只有 2–5mV，只有 3–6 个 LSB，必须靠滤波和过采样
- 测电流用 0.01Ω 采样电阻，1A 时压降只有 10mV，也不过 12 个 LSB

**这就是为什么高精度测量要用外部 ADC 或仪表放大器**——12 位对很多场合是不够的。

## 4.2 采样时间：为什么源阻抗不能太大

ADC 内部有一个采样保持电容（约 8pF），采样期间它通过一个内部开关（约 1kΩ）连接到引脚，对引脚上的电压充电。**只有电容电压充到与引脚电压足够接近，读出来的值才准。**

充电速度取决于总电阻：内部开关电阻 + 外部信号源内阻。这是一个 RC 电路：

$$
\tau = R_{total} \times C_{sample}
$$

采样时间是有限的，要保证充电到 0.5 LSB 精度以内，一般需要 **9~10 个时间常数**。

结论很直接：**信号源内阻越大，需要的采样时间越长。**

| 源阻抗 | 建议采样时间 | 说明 |
|---|---|---|
| < 1 kΩ | 1.5 – 7.5 周期 | 运放输出、低阻分压 |
| 1 – 10 kΩ | 13.5 – 41.5 周期 | 常见分压电阻网络 |
| 10 – 100 kΩ | 71.5 – 239.5 周期 | 必须加长，且降低采样率 |
| > 100 kΩ | 不推荐 | 应加电压跟随器 |

**常见错误：用两个 100kΩ 电阻分压测电池电压，ADC 配成最快采样时间。** 结果是读数偏低且跳变——因为电容还没充满就被读走了。改成 10kΩ 分压，或者把采样时间调到 239.5 周期，问题立刻消失。

这里有个权衡：采样时间越长，总转换时间越长。转换时间公式：

$$
T_{conv} = \frac{(\text{采样周期} + 12.5)}{f_{ADC}}
$$

STM32F1 的 ADC 时钟最大 14MHz。如果采样时间取 239.5 周期：

$$
T_{conv} = \frac{239.5 + 12.5}{14\text{MHz}} = 18\ \mu s
$$

换算成采样率约 55kSPS。如果取 1.5 周期：

$$
T_{conv} = \frac{1.5 + 12.5}{14\text{MHz}} = 1\ \mu s
$$

即 1MSPS。**这就是为什么"最高采样率"和"最高精度"永远不能同时达到。**

## 4.3 三种工作模式与 DMA

### 单次转换

```c
HAL_ADC_Start(&hadc1);
HAL_ADC_PollForConversion(&hadc1, 10);
uint16_t v = HAL_ADC_GetValue(&hadc1);
```

最简单，适合低速、单通道、按需读取的场合。缺点是每次都要软件触发，CPU 参与度高。

### 连续转换 + 轮询

ADC 自己不停转换，CPU 需要时去读最新值。适合实时性要求不高的监测（比如温度）。

### 扫描 + DMA（工程推荐）

多通道场景的标准做法：ADC 依次转换规则组里的每个通道，每完成一个就由 DMA 自动搬到内存数组，全程不需要 CPU 介入。

```c
uint16_t adc_buf[3];   /* 三个通道 */

HAL_ADC_Start_DMA(&hadc1, (uint32_t *)adc_buf, 3);

/* 之后随时读 adc_buf[0..2] 即可，DMA 会自动刷新 */
```

配置要点：

1. ADC 的 **Continuous Conversion Mode** 使能
2. **DMA Continuous Requests** 使能
3. 规则组里按顺序添加通道
4. DMA 模式设为 **Circular**（循环），否则搬完一轮就停了

**DMA 循环模式是这里的关键。** 如果用 Normal 模式，第一轮转换完成后 DMA 停止，`adc_buf` 里永远是旧值，你会以为 ADC 卡死了。

[[anim:dma-transfer]]

点一下动画里的「Normal 单次」，你会看到 CNDTR 从 8 倒数到 0、EN 位自动清零，之后数组再也没变过——这就是只配了一半 DMA 的典型现场：ADC 还在欢快地转换，`adc_buf` 却卡在最后一帧。改成「Circular 循环」，CNDTR 会重新装回 8、CMAR 回到 `buf[0]`，指针自己转圈，永不停机。

另一个容易忽略的点是**数组的读取一致性**：DMA 随时可能在改 `adc_buf`，你读到一半时它换了一轮，就会出现「前两个通道是新值、第三个是旧值」的撕裂。工程上的做法是双缓冲（DMA 半满/全满中断各切一次），或者让 DMA 只在缓冲区未使用时搬运。

## 4.4 从原始值到有用的数字

### 均值滤波

最简单的降噪：连采 N 次取平均。

```c
uint16_t adc_avg(uint8_t ch, uint8_t n)
{
    uint32_t sum = 0;
    for (uint8_t i = 0; i < n; i++) {
        HAL_ADC_Start(&hadc1);
        HAL_ADC_PollForConversion(&hadc1, 10);
        sum += HAL_ADC_GetValue(&hadc1);
    }
    return sum / n;
}
```

N 取 8 或 16，信噪比改善约 $\sqrt{N}$ 倍（8 次约 2.8 倍）。代价是耗时增加 N 倍。

### 中值滤波 + 均值

均值滤波怕脉冲干扰（一次异常值就能污染结果）。实用组合是"去掉最大最小再平均"，或者取中位数。对按键、传感器这类偶发跳变的信号效果好得多。

### 过采样（Oversampling）

这是提升有效分辨率的正规方法。原理：把信号采样 $4^n$ 次并累加，右移 $n$ 位。理论上每 4 倍过采样能增加 1 位有效分辨率。

```c
/* 256 次过采样，理论提升 4 位（12 → 16 位） */
uint32_t sum = 0;
for (int i = 0; i < 256; i++) {
    HAL_ADC_Start(&hadc1);
    HAL_ADC_PollForConversion(&hadc1, 10);
    sum += HAL_ADC_GetValue(&hadc1);
}
uint16_t value_16bit = sum >> 4;   /* 除以 16，得到 16 位结果 */
```

**但要注意前提**：过采样只能压低随机噪声，前提是噪声确实是随机的、且幅度大于 1 LSB。如果信号本身完全干净（噪声小于 1 LSB），过采样不会带来任何精度提升，只是把同一个值重复加了 256 次。

STM32F3/F4 及更新的系列有硬件过采样单元，配好参数直接出结果，不需要软件循环。

### 校准

STM32F1 的 ADC 上电后建议执行一次校准：

```c
HAL_ADCEx_Calibration_Start(&hadc1);
```

校准补偿的是内部电容失配带来的固定偏移。不校准也能用，但零点误差可能有几个 LSB。**注意校准必须在 ADC 使能之后、开始转换之前调用，且校准时不能有转换在进行。**

## 4.5 精度陷阱：读数为什么会飘

12 位理论精度是 0.8mV，但实际工程中经常看到 ±30mV 的跳动。原因通常不在 ADC 本身：

**陷阱一：参考电压不稳。**
`V_ref` 直接取自 3.3V 电源轨，而电源轨上有开关电源纹波、数字电路瞬态电流造成的跌落。**ADC 测的是"输入相对于 Vref 的比例"，Vref 一抖，所有读数一起抖。**

解决办法有二：一是给 Vref 加 100nF + 10μF 去耦；二是改用外部精密基准（如 TL431、REF3033），并接到 `VREF+` 引脚。注意 STM32F103 的 100 脚以下封装（如 LQFP48）**没有独立 VREF+ 引脚**，Vref 内部连到 VDDA，无法外接基准——这是选型时必须考虑的限制。

**陷阱二：地线反弹（ground bounce）。**
ADC 的 AGND 和数字 GND 如果在芯片内部共用一段引线，大电流数字开关会在上面产生压降，叠加到 ADC 的参考地上。PCB 布局上应该让模拟地和数字地单点连接，ADC 相关器件靠在一起。

**陷阱三：输入超过量程。**
输入电压超过 Vref 会导致读数饱和在 4095，但更危险的是超过 VDDA + 0.3V 会触发内部钳位二极管，长时间会把引脚打坏。测高压必须分压，且分压后要加钳位保护（如 BAT54S 双肖特基）。

**陷阱四：引脚配错模式。**
ADC 输入引脚必须配置为 **模拟输入（GPIO_MODE_ANALOG）**。如果配成浮空输入或上拉输入，内部上拉电阻会参与分压，读数完全不对。这是配置 ADC 最高频的错误。

**陷阱五：多通道间串扰。**
扫描模式下通道切换后，采样电容残留上一个通道的电荷。如果前一个通道是高电压、后一个是低电压，会看到后一个偏高。对策是加长采样时间，或者在通道间插入一次空转换。

## 4.6 本章小结

- 1 LSB = Vref / 4096，3.3V 下约 0.806mV，这是精度的物理下限。
- 采样时间是给内部采样电容充电用的，源阻抗越大需要越长；> 10kΩ 必须延长采样或加运放跟随。
- 转换时间 = (采样周期 + 12.5) / f_ADC，采样率与精度不可兼得。
- 多通道用扫描 + DMA 循环模式，CPU 零参与。
- 提升精度靠滤波和过采样，但过采样只对随机噪声有效。
- 读数漂移多半不是 ADC 的错，先查参考电压、地线、引脚模式。
