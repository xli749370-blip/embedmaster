# 第二章 中断与 NVIC：让 CPU 停止空等

> 上一章的按键扫描用的是定时器轮询。轮询的问题不在于"慢"，而在于它的代价是固定的——不管有没有事件，CPU 都必须按时回来检查一次。中断把这件事倒过来：没事的时候 CPU 去干正事，有事了硬件把它拽回来。

## 2.1 轮询的成本账

假设用 1ms 的轮询周期检测 10 个 IO：

- 每次轮询读 10 个引脚，约 20 条指令，在主频 72MHz 下约 0.3μs
- 每秒执行 1000 次，累计 0.3ms
- **CPU 占用率 0.03%，看起来微不足道**

但真正的问题不是占用率，而是**响应延迟**。如果事件发生在刚检查完之后，最多要等 1ms 才能被发现。对于按键，1ms 完全够用；对于编码器脉冲、串口数据、飞控的姿态环，1ms 是致命的——等你发现时数据已经覆盖丢失了。

把轮询周期缩短到 10μs 能降低延迟，但 CPU 占用率立刻涨到 3%，而且随着外设数量增加线性恶化。**中断的意义是：它让响应延迟与 CPU 占用脱钩。** 没有事件时 CPU 占用是 0，有事件时延迟是硬件级的几个时钟周期。

## 2.2 一个中断从发生到执行

以外部中断（EXTI）为例，完整链路是这样的：

```
引脚电平变化
    ↓
EXTI 边沿检测器（上升沿/下降沿/双边沿）
    ↓
挂起寄存器 EXTI_PR 置位
    ↓
NVIC 仲裁（比较优先级，决定是否打断当前任务）
    ↓
CPU 保存现场（8 个寄存器自动入栈，12 个时钟周期）
    ↓
从向量表取出 ISR 地址，跳转执行
    ↓
ISR 内部：清标志 → 处理 → 返回
    ↓
CPU 恢复现场（出栈，12 个时钟周期）
```

两个容易出错的地方：

**第一，标志位必须手动清除。** EXTI 挂起标志不会自动清，如果 ISR 里忘了清，退出后 NVIC 立刻认为又有一次中断，于是死循环式地反复进入。表现是程序卡死在 ISR 里、主循环完全不跑。

```c
void EXTI0_IRQHandler(void)
{
    /* HAL 的 HAL_GPIO_EXTI_IRQHandler 内部会清标志并调用回调 */
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0);
}

/* 用户回调：只写这个函数，不要直接写 IRQHandler */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0) {
        /* 处理逻辑 */
    }
}
```

**第二，现场保存需要 12 个时钟周期，恢复又需要 12 个。** 也就是说一次中断进出本身就有约 0.33μs 的固定开销（72MHz 下）。如果一个中断每秒触发 10000 次，光进出开销就吃掉 3.3ms/s。所以**高频事件不要用中断，用 DMA**。

## 2.3 NVIC 优先级：抢占与子优先级

Cortex-M3/M4 的 NVIC 支持 4 位优先级，意味着 16 个等级（0–15）。**数值越小，优先级越高**，这一点和直觉相反，是配置错误的重灾区。

这 4 位可以被切分成"抢占优先级"和"子优先级"两部分，切分方式由优先级分组决定：

| 分组 | 抢占位 | 子优先级位 | 抢占级数 | 子级数 |
|---|---|---|---|---|
| Group 0 | 0 | 4 | 1 | 16 |
| Group 2 | 2 | 2 | 4 | 4 |
| Group 3 | 3 | 1 | 8 | 2 |
| **Group 4** | **4** | **0** | **16** | **1** |

**抢占优先级（Preemption）**决定能否打断正在执行的中断。**子优先级（Subpriority）**只在多个中断同时挂起时决定谁先执行，**不能打断**——两个子优先级不同的中断不会互相抢占。

工程上最简单也最不容易出错的做法是**统一用 Group 4**（4 位全给抢占优先级，无子优先级），这样"数值小的能打断数值大的"这一条规则就覆盖了全部情况，不需要再记忆子优先级的特殊行为。

```c
/* 在 main 开头设置一次即可 */
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);

/* 优先级 1 给最紧急的：飞控姿态环、电机 PWM 更新 */
HAL_NVIC_SetPriority(TIM1_UP_IRQn,  1, 0);
/* 优先级 5：串口接收 */
HAL_NVIC_SetPriority(USART1_IRQn,   5, 0);
/* 优先级 15：按键、LED 刷新 */
HAL_NVIC_SetPriority(EXTI0_IRQn,   15, 0);
HAL_NVIC_EnableIRQ(EXTI0_IRQn);
```

### 优先级配置错误会怎样

**症状一：串口丢数据，但波特率是对的。**
如果串口中断优先级低于某个频繁触发的中断（比如 1kHz 的定时器），串口字节间隔 87μs（115200bps 下），而低优先级中断被连续抢占，接收移位寄存器里的数据就会在下一字节到来前被覆盖。HAL 会置 `ORE`（溢出错误）标志，之后整个串口停止工作——**因为 HAL 在 ORE 状态下会锁死接收**，必须手动清标志并重启接收。

**症状二：偶发死机，复位后正常，无法复现。**
通常是两个中断互相抢占形成嵌套过深，或者高优先级中断里调用了依赖低优先级中断的函数。经典案例：**在中断里调用 `HAL_Delay()`**。

`HAL_Delay` 依赖 SysTick 中断累加计数。如果你的中断优先级高于 SysTick（SysTick 默认是最低优先级 15），那么在中断里调 `HAL_Delay` 会永远等不到计数增加——CPU 卡死在中断里，看门狗复位。这个 bug 的恶劣之处在于：单独测试时中断可能没触发，一上整机就死。

**症状三：FreeRTOS 下中断不触发，或者一触发就进 HardFault。**
FreeRTOS 要求：**凡是用 FreeRTOS API 的中断，其优先级数值必须 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`**（即优先级不能比它更高）。超出这个范围的中断不能调用 `xxxFromISR()` 系列函数，否则会破坏内核临界区，导致随机崩溃。

**嵌套到底长什么样？** 抢占优先级不同时，高优先级中断会立刻打断低优先级中断，形成"中断里再套中断"。被套住的中断不会丢——它的现场（PC、LR、通用寄存器）被压在栈上，等外层处理完再逐层恢复。下面这个动画把 40 个节拍里的抢占与恢复完整演了一遍，重点看 t=7（TIM1 抢占 USART1）和 t=10（弹栈恢复）两个时刻。

## 2.4 ISR 里的纪律

中断服务函数只有一个原则：**尽快返回。** 具体拆成五条：

### 一、只做"必须立刻做"的事

ISR 里应该只做三件事：读走数据、清标志、置一个软件标志位通知主循环。所有耗时运算（浮点、滤波、协议解析、打印）都搬到主循环。

```c
volatile uint8_t g_frame_ready = 0;

void USART1_IRQHandler(void)
{
    HAL_UART_IRQHandler(&huart1);      /* HAL 内部把数据收进缓冲区 */
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    g_frame_ready = 1;                 /* 只置标志，不解析 */
    HAL_UART_Receive_IT(huart, buf, 1); /* 重新挂上接收 */
}
```

### 二、共享变量必须加 volatile

```c
volatile uint8_t g_frame_ready = 0;   /* 正确 */
uint8_t          g_frame_ready = 0;   /* 错误 */
```

没有 `volatile`，编译器会认为"这个变量只在主循环里被读，值不会变"，于是把它优化进寄存器，`while(!g_frame_ready)` 就变成死循环。**开了 -O2 才出现、关掉优化就正常的 bug，九成是漏了 volatile。**

`volatile` 保证每次从内存重新读取，但它**不保证原子性**。多字节变量（如 `uint32_t` 在 8 位机上）读写可能被中断打断，需要加临界区保护。

### 三、不要在 ISR 里做浮点运算（特殊情况）

Cortex-M3 没有 FPU，浮点靠软件模拟，一次除法可能几百个周期。Cortex-M4F 有硬件 FPU，但**FPU 寄存器属于"惰性入栈"**，如果 ISR 里用浮点，会额外增加入栈开销；更麻烦的是在 RTOS 环境下需要正确配置 `FPU` 上下文，否则任务切换时浮点寄存器会错乱。

保守原则：**ISR 里只做整数运算。**

### 四、不要在 ISR 里打印

`printf` 内部有锁、有格式化、可能阻塞在串口发送上。在 ISR 里调用 `printf` 几乎必然导致时序崩溃。需要调试输出时，把数据塞进一个无锁环形缓冲区，主循环里再打印。

### 五、临界区要短

关闭中断保护共享数据时，临界区越短越好：

```c
uint32_t primask = __get_PRIMASK();
__disable_irq();
/* 只放几行必要代码 */
counter++;
__set_PRIMASK(primask);   /* 恢复之前的开关状态，不是简单 __enable_irq() */
```

注意恢复时用 `__set_PRIMASK(primask)` 而不是 `__enable_irq()`。假如这段临界区本身就在另一个临界区里（或从 ISR 中调用），直接开中断会破坏外层保护。

## 2.5 EXTI 的几个细节

**同一个 Pin 号只能选一个端口。** PA0、PB0、PC0 共用 EXTI0 这条线，同一时刻只能有一个作为中断源。选了 PA0 就不能同时用 PB0 做外部中断。

**边沿检测要配在正确的地方。** 除了 EXTI 的边沿触发配置，GPIO 本身也要配成输入模式（上拉/下拉/浮空）。常见错误是只配了 EXTI 没配 GPIO，结果永远不触发。

**中断频率要估算。** 机械按键、传感器数据就绪适合用中断；编码器 A/B 相、高速脉冲计数这类高频信号，中断开销会成为瓶颈，应该用定时器的编码器模式或输入捕获，由硬件计数。

**软件触发调试法。** 想验证中断链路是否打通，可以用 `NVIC_SetPendingIRQ(IRQn)` 手动挂起一次，看是否进 ISR。这比反复拨线可靠得多。

## 2.6 本章小结

- 中断的价值是让响应延迟与 CPU 占用率脱钩，代价是进出的固定开销（约 24 个时钟周期）。
- 优先级数值越小越高；建议统一用 Group 4，避免子优先级的反直觉行为。
- ISR 里忘清标志会死循环；中断里调 `HAL_Delay` 会永久卡死；漏 `volatile` 会在 -O2 下出鬼。
- ISR 只做"读数据 + 清标志 + 置标志"，运算和打印全部搬到主循环。
- 高频事件不用中断，用 DMA 或外设硬件的计数器。
