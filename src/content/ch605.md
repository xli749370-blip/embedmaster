# 第五章 通信协议与上位机联调：让手机读懂数据

> 串口透传只能发字符串，无法区分"温湿度"还是"电池电压"，更挡不住误码。这一章定义一帧结构化协议，并完成 MCU 与手机小程序的联调。

## 5.1 帧格式定义

沿用第一章的雏形，落地为可实现的 12 字节定长帧 + 可选变长：

```
| 0xAA | 0x55 | LEN | CMD | DATA[n] | CRC16_LO | CRC16_HI |
  1B     1B     1B    1B     n 字节    1B         1B
```

- `LEN` = `n`，即 DATA 字节数（不含帧头与 CRC）。
- `CMD` 命令字：`0x01` 温湿度上报、`0x02` 电池电压、`0x03` 配置上报周期、`0x04` ACK。
- `CRC16` 对 `LEN` 起到 `DATA` 末尾全部字节计算，低字节在前。

## 5.2 CRC16 计算与校验

采用 CRC-16/MODBUS（`poly=0x8005`，初始 `0xFFFF`，低位在前）：

```c
uint16_t crc16(const uint8_t *p, uint16_t len) {
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= p[i];
        for (int j = 0; j < 8; j++)
            crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : (crc >> 1);
    }
    return crc;   // 发送时先发低字节后发高字节
}
```

接收端对整帧（除最后 2 字节）重算 CRC，与帧尾比较，不等则丢弃重收。

> 为什么不用 checksum？校验和只是加法，两个字节同时翻转可能抵消；CRC 对连续位错极其敏感，蓝牙空中误码用它更稳。

## 5.3 组帧与发送

```c
void frame_send(uint8_t cmd, const uint8_t *data, uint8_t n) {
    uint8_t buf[32];
    buf[0] = 0xAA; buf[1] = 0x55; buf[2] = n; buf[3] = cmd;
    memcpy(&buf[4], data, n);
    uint16_t c = crc16(&buf[2], n + 2);     // 对 LEN+CMD+DATA 算
    buf[4 + n] = c & 0xFF;
    buf[5 + n] = c >> 8;
    ble_send(buf, n + 6);
}
```

温湿度上报：把 `temp`（×100 整数）、`hum`（×100 整数）打包成 4 字节 DATA，手机端 ÷100 还原。用**定点**而非浮点，省算力也省字节。

## 5.4 接收端解析（手机小程序侧）

小程序通过蓝牙 `onBLECharacteristicValueChange` 拿到 `ArrayBuffer`，按字节流处理：

```
收到字节流 → 找 0xAA 0x55 帧头 → 读 LEN → 等够 LEN+CRC → 校验 CRC
        ├─ CRC 错 → 丢弃并滑动找下一个帧头（处理粘包/断包）
        └─ CRC 对 → 按 CMD 分发：0x01 更新温湿度卡片
```

关键三点：

1. **字节序统一**：MCU 发的是小端 uint16，小程序 `DataView.getUint16(off, true)` 读取。
2. **粘包/断包**：一包可能夹两帧，也可能一帧被拆两包，必须维护一个**接收缓冲**累加处理。
3. **超时丢弃**：半帧停留超 200 ms 直接清空，避免脏数据卡死解析。

## 5.5 联调手段

| 问题层 | 工具 | 看什么 |
| --- | --- | --- |
| I2C 物理层 | 逻辑分析仪 | SCL/SDA 波形、ACK、地址 |
| 串口/UART | 串口助手 | 透传内容、波特率是否匹配 |
| 协议层 | 自写解析脚本 | CRC 是否通过、字段是否正确 |
| 手机端 | 小程序调试器 | onBLEValue 收到的原始字节 |

> 经典坑：蓝牙模块默认 9600，MCU 配成 115200，两边"握手成功但内容乱码"——先确认两端波特率一致再调协议。

## 5.6 常见问题排查

1. **收不到数据**：先确认蓝牙是否真的透传（有些模块默认 AT 模式，需特定指令切透传）。
2. **数据错乱**：几乎都是字节序或定点缩放（`÷100` 忘写）问题。
3. **偶发丢帧**：CRC 把误码帧丢了，多半是空中干扰或波特率临界，降速到 9600 验证。
4. **粘包解析错位**：没有维护接收缓冲，按"够长度就解析"会漏掉半帧。

## 本章要点

- 定长帧：帧头 AA55 + LEN + CMD + DATA + CRC16（低字节在前）
- CRC16/MODBUS 比 checksum 更抗误码
- 组帧发送、接收端缓冲累加处理粘包/断包
- 字节序统一用小端 `getUint16(off, true)`，定点 ×100 传浮点
- 联调分层：逻辑分析仪(I2C) → 串口助手(UART) → 解析脚本(协议) → 小程序
- 收不到先查透传模式，乱码先查波特率与字节序
