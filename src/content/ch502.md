## 2.1 任务是什么

在 FreeRTOS 里，一个任务就是「**一个不返回的循环函数 + 一块独立的栈 + 一张任务控制块（TCB）**」。

```c
void task_sample(void *pvParameters) {
    for (;;) {                 // 注意：任务函数绝不能 return
        do_work();
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}
```

- **函数体**：一个死循环。任务不是「被调用一次就结束」的普通函数，而是 OS 长期持有的执行流。
- **栈**：函数里的局部变量、返回地址都存在**这块专属栈**里。正因为每个任务有独立栈，它们才能各自调用函数、各自递归，互不影响。
- **TCB（Task Control Block）**：内核为每个任务维护的结构体，记录它的栈顶指针、当前状态、优先级、延时到期时间等。调度器「认识」一个任务，靠的就是它的 TCB。

创建任务用 `xTaskCreate`（动态分配栈与 TCB）或 `xTaskCreateStatic`（用你给的静态数组，确定性更强）。

## 2.2 四个状态

每个任务在任一时刻必处以下四种状态之一：

| 状态 | 含义 | 进入方式 |
| --- | --- | --- |
| **运行 Running** | 正占用 CPU | 被调度器选中 |
| **就绪 Ready** | 能跑，但优先级不是最高 | 刚创建、或被更高优先级任务抢占后 |
| **阻塞 Blocked** | 在等某件事（延时到期 / 队列数据 / 信号量） | `vTaskDelay`、等队列、等信号量 |
| **挂起 Suspended** | 被「冻住」，不参与调度 | `vTaskSuspend`，需 `vTaskResume` 唤醒 |

关键点：**阻塞态的任务不占 CPU**。这正是 RTOS 高效的根源——需要等待的任务主动退出竞争，把处理器让给就绪的伙伴。一个任务 `vTaskDelay(1000)` 的一秒内，CPU 完全可以去跑别的任务，而不是空转。

## 2.3 调度器在做的事

调度器的工作极其单纯：在**所有就绪任务**里，挑「优先级最高」的那个投入运行。一句话，却藏着全部复杂度的来源。

- **抢占式（Preemptive）**：只要出现一个优先级更高的就绪任务，当前任务立刻被换下。这是默认模式，也是「实时性」的保证。
- **协作式（Cooperative）**：只有当前任务主动 `taskYIELD()` 或阻塞，才会让出 CPU。低优先级任务不会被强行打断，但一个死循环会饿死所有人——极少使用。

## 2.4 优先级：数值约定是个大坑

> **FreeRTOS 的优先级数值越大，优先级越高；而 Cortex-M 的 NVIC 中断优先级数值越小越高。两者恰好相反。**

这几乎是每个初学者必踩一次的坑。在 FreeRTOS 中：

- `0` 是最低优先级，通常留给**空闲任务（Idle Task）**；
- `configMAX_PRIORITIES - 1` 是最高；
- 你创建任务时给的 `uxPriority` 就在这个范围内。

所以「让温控任务优先级高于显示任务」意味着给它一个**更大**的数字。记不住就记住这句话：**FreeRTOS 里「大」就是「狠」**。

## 2.5 时间片：同优先级怎么分

如果两个任务优先级相同，难道永远只有一个跑？不会。调度器给同优先级任务分配**时间片（Time Slice）**：每个任务最多连续跑一个时间片（默认等于一个系统节拍 `tick`，如 1ms），到点就被换到同优先级的下一个就绪任务。这叫**轮转调度（Round Robin）**。

时间片让「平级」的任务能公平分享 CPU。如果你不想要时间片（比如两个同优先级任务本就一快一慢），可以把 `configUSE_TIME_SLICING` 关掉，此时同优先级任务会一直跑到自己阻塞才让出。

## 2.6 就绪表与优先级位图

就绪任务成千上万时，调度器怎么在几微秒内找到最高优先级？靠**就绪表 + 优先级位图**：

- 内核维护一个「位图」，第 `i` 位为 1 表示「优先级 `i` 有就绪任务」；
- 找最高优先级 = 找位图里**最左侧的 1**，硬件有 `CLZ`（Count Leading Zeros）指令，$O(1)$ 完成；
- 同一优先级可能有多个任务，挂在一个链表上，按时间片轮转。

这意味着：**无论有多少任务，挑最高优先级的时间基本恒定**。这是 RTOS 能撑住大系统的关键设计，和你手写 `if/else` 链遍历所有任务有本质区别。

## 2.7 空闲任务：别小看最低优先级

调度器启动后，如果某一瞬间「没有任何用户任务就绪」（大家都阻塞了），CPU 不能停，于是运行**空闲任务**——它优先级最低，专门在没活干时占位。你可以挂接「空闲钩子」`vApplicationIdleHook` 在里面做低功耗、看门狗喂狗，或者统计 CPU 空闲率。空闲任务还负责回收被删除任务的内存，所以**永远不要阻塞或挂起空闲任务**。

## 2.8 一个配置清单

动手前先看清这几个宏（`FreeRTOSConfig.h`）：

- `configMAX_PRIORITIES`：可用优先级数。别随手设 32，每多一级就多一点内核开销，通常用得到的也就 5~8 级。
- `configTICK_RATE_HZ`：系统节拍频率，决定时间片与延时粒度。1000Hz = 1ms 精度，但节拍中断本身也有开销。
- `configUSE_PREEMPTION`：是否抢占（一般开）。
- `configUSE_TIME_SLICING`：同优先级是否轮转。

理解了任务和优先级，下一章我们看「切换」这件事到底在硬件层面怎么发生——它是 RTOS 最神秘、也最值得动手看一眼的过程。
