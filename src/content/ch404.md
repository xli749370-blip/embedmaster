# 第四章 中断上下文与并发陷阱

> 上一章说共享变量要加 `volatile`。这句话是对的，但只对一半。`volatile` 解决的是"编译器不知道有人改"，解决不了"改到一半被打断"。这一章讲后者。

## 4.1 volatile 能保证什么，不能保证什么

```c
volatile uint32_t g_count = 0;

void TIM2_IRQHandler(void) { g_count++; }   /* 中断里累加 */

int main(void)
{
    g_count++;    /* 主循环里也累加 */
}
```

两边都加了 `volatile`，编译器会老老实实每次读写内存。**但结果仍然是错的。**

因为 `g_count++` 编译出来是三条指令：

```
LDR  r0, [g_count]    ; ① 读
ADD  r0, r0, #1       ; ② 加
STR  r0, [g_count]    ; ③ 写回
```

如果在 ① 和 ③ 之间来了中断，中断里完整执行了一遍 `g_count++`，返回后主循环用**它读到的旧值**加 1 写回，中断那一次的增量就被覆盖了。

这就是"读-改-写"（read-modify-write）问题。它不是编译器优化造成的，是**执行序列本身可以被打断**。`volatile` 对此无能为力。

## 4.2 原子性的三个层次

判断一段代码是否安全，要分三层看：

| 层次 | 含义 | 例子 |
|---|---|---|
| **单次访问原子** | 一条指令完成，中间不会被打断 | 对齐的 `uint32_t` 读写、`uint8_t` 读写 |
| **读改写原子** | 读、改、写三步不可分割 | `i++`、`reg \|= mask`、`x *= 2` |
| **多变量一致** | 几个变量作为一个整体更新 | 更新 `{value, timestamp}` 对 |

### 第一层：Cortex-M 上的单次访问是原子的

在 Cortex-M 上，**对齐的** 32 位、16 位、8 位读写都是单条指令，天然原子。所以：

```c
volatile uint32_t g_flag;      /* 主循环写 1，中断读 —— 安全 */
volatile uint8_t  g_byte;      /* 安全 */
```

但有两个例外必须知道：

**非对齐访问不原子。** 假设 `uint32_t` 变量跨了 4 字节边界（只在 `packed` 结构体里会这样），硬件要拆成两次访问，中途可能被中断插入。

**`double`/`int64_t` 不原子。** 64 位数据要两条 32 位指令读，中间可能被改，读到的可能是"高 32 位是新值、低 32 位是旧值"的缝合怪。做时间戳、累加器时要注意。

### 第二层：读改写一定不原子

```c
i++;            /* LDR / ADD / STR，三条 */
reg |= mask;    /* LDR / ORR / STR，三条 */
x *= 2;         /* 同上 */
```

只要有三条指令，中断就能插在中间。解决方式三选一：关中断、用原子指令、改变算法（单写者模式）。

### 第三层：多变量一致

```c
/* 中断里更新 */
g_value = adc_value;
g_valid = 1;

/* 主循环里读 */
if (g_valid) { use(g_value); }    /* 可能读到新 value、旧 valid，或反过来 */
```

两个 `volatile` 变量各自原子，但**组合起来不原子**。这类问题只能靠关中断、双缓冲或序列号（seqlock）解决。

## 4.3 临界区：关中断的正确姿势

最直接的办法是关中断，但写法有讲究。

### 错误写法：直接开关

```c
void bad_critical(void)
{
    __disable_irq();
    g_count++;
    __enable_irq();     /* 无条件开中断 */
}
```

问题在于**嵌套**。如果外层已经关了中断（比如在另一个临界区里，或者本来就在 ISR 里调用），这段代码退出时会无条件打开中断——外层以为还关着，实际上已经开了，保护失效。

### 正确写法：保存并恢复

```c
void good_critical(void)
{
    uint32_t primask = __get_PRIMASK();   /* 记住原来关没关 */
    __disable_irq();
    g_count++;
    __set_PRIMASK(primask);               /* 恢复原状态，而不是无条件开 */
}
```

`PRIMASK` 是 Cortex-M 的一个特殊寄存器，bit0 = 1 表示"屏蔽所有可配置优先级的中断"。保存它、恢复它，嵌套就自然正确了。

CMSIS 把这对操作封装成了宏，省得每次写四行：

```c
__disable_irq();
/* ... */
__enable_irq();
```

但**嵌套场景下 `__enable_irq()` 仍然是无条件开**。RTOS 里通常用 `taskENTER_CRITICAL()` / `taskEXIT_CRITICAL()`，它们内部维护了嵌套计数，就是为了解决这个问题。

### 临界区的三条纪律

1. **越短越好**。关中断期间，所有中断都得不到响应。串口会丢字节、编码器会漏脉冲。一个临界区超过几十微秒就该重新设计
2. **里面不调用任何函数**。你不知道 `HAL_Delay()` 会不会在里面等 1ms；更常见的是在临界区里调 `printf`，直接把系统卡死
3. **不在里面用浮点**。会触发惰性压栈，时间不可预测

一个具体的坏例子：

```c
/* 反面教材：在临界区里做耗时操作 */
__disable_irq();
for (uint32_t i = 0; i < len; i++) buf[i] = src[i];   /* 拷 512 字节 */
__enable_irq();
```

改成"关中断只保护索引更新，拷贝放外面"：

```c
__disable_irq();
uint32_t n = pending_len;      /* 只取一个快照，几纳秒 */
pending_len = 0;
__enable_irq();
/* 拷贝在中断开启的状态下慢慢做 */
memcpy(buf, src, n);
```

## 4.4 不用关中断的三种做法

关中断是"最粗暴但最可靠"的手段。有几种场景可以避开它，代价是设计更复杂但实时性更好。

### 做法一：单写者模式

如果一个变量**只有一个地方写**（比如只在 ISR 里写），主循环只读，那么读写都是原子的，完全不需要保护：

```c
volatile uint32_t g_tick;    /* 只在 SysTick ISR 里 ++，主循环只读 */

/* 主循环里这样读会有撕裂风险吗？ */
uint32_t now = g_tick;       /* 不会：单次 LDR，原子 */
```

这是最常用的模式。环形缓冲区的 `head`（ISR 写、主循环读）和 `tail`（主循环写、ISR 读）就是它——所以标准环形缓冲区是**无锁**的。

### 做法二：原子指令

Cortex-M3/M4 提供 `LDREX` / `STREX`（独占访问），M0 没有。CMSIS 和 GCC 都做了封装：

```c
/* GCC 内建函数，Cortex-M3 以上会编译成 LDREX/STREX 循环 */
uint32_t old = __atomic_fetch_add(&g_count, 1, __ATOMIC_SEQ_CST);
```

CMSIS 也有对应的：

```c
uint32_t old = __LDREXW(&g_count);    /* 独占读 */
__STREXW(old + 1, &g_count);          /* 独占写，返回 0 表示成功 */
```

`STREX` 会失败——如果读和写之间有别的访问者动过这个地址，它返回非零，需要重试。所以原子操作通常写成循环：

```c
do {
    old = __LDREXW(&counter);
} while (__STREXW(old + 1, &counter) != 0);
```

好处是不用关中断；坏处是代码更长，而且在 M0 上不适用（M0 没有独占访问指令，只能关中断）。

### 做法三：把"共享"变成"传递"

最彻底的方案是让数据只有一个所有者，通过队列传递。ISR 只往队列里放，主循环只从队列里取，两边不碰同一个变量：

```c
/* ISR 里：放数据，只动 head */
ring_push(&rx_ring, byte);

/* 主循环里：取数据，只动 tail */
if (ring_pop(&rx_ring, &b)) { process(b); }
```

这就是"单生产者单消费者"模型，也是串口、ADC、DMA 场景的标配。它的正确性不依赖关中断，只依赖 `head`/`tail` 各自的单写者属性和 `volatile`。

## 4.5 一个真实 bug 的完整推演

串口用 DMA 收数据，代码长这样：

```c
volatile uint16_t rx_len = 0;      /* 中断里写入本帧长度 */
uint8_t rx_buf[256];

void USART1_IRQHandler(void)
{
    if (idle_flag) {
        rx_len = 256 - DMA_GetCurrDataCounter();   /* 算出这帧多少字节 */
        frame_ready = 1;
    }
}

int main(void)
{
    while (1) {
        if (frame_ready) {
            parse(rx_buf, rx_len);    /* 用这个长度去解析 */
            frame_ready = 0;
        }
    }
}
```

看起来没问题：`rx_len` 和 `frame_ready` 都是 `volatile`，中断先写长度再置标志。但会偶发解析到乱码，原因有两个：

**① 顺序没有保证。** 编译器可以重排两个 `volatile` 写吗？不能（`volatile` 之间不重排）。但 Cortex-M 有写缓冲，**两个写可能以不同顺序到达内存**——`frame_ready = 1` 先落地，`rx_len` 还在缓冲里，主循环看到标志却读到了旧长度。

修法是加屏障：

```c
rx_len = ...;
__DMB();            /* 数据内存屏障：确保前面的写在后面之前对所有观察者可见 */
frame_ready = 1;
```

**② 主循环里清标志的顺序反了。** 如果先把 `frame_ready = 0`，再处理数据，下一次中断可能已经置了新的 `frame_ready`，被这句清零吃掉，丢一帧。正确顺序是"先处理、最后清标志"——上面的代码其实是对的，但很多人写反。

这个 bug 的教训是：**`volatile` 保证可见性，不保证顺序。** 跨"执行环境"（中断 vs 主循环）传递数据时，要考虑三件事：可见性（`volatile`）、顺序（`__DMB()`）、完整性（结构体还是单变量）。

## 4.6 什么函数不能进中断

中断服务函数是一个**共享的、抢占了别人执行流的**环境。判断一个函数能不能在 ISR 里调用，只看一条：**它是否可重入（reentrant）**。

不可重入的判定标准：

- 用了全局或静态变量（且没有保护）
- 调用了 `malloc`/`free`
- 调用了不可重入的库函数
- 内部有"读-改-写"序列

常见陷阱：

| 函数 | 为什么不能在 ISR 里调 |
|---|---|
| `printf` / `sprintf` | newlib 的实现用全局缓冲区，主循环正在打印时进 ISR 再打印会乱码或死锁 |
| `malloc` / `free` | 堆管理器的空闲链表操作不是原子的，会破坏堆结构 |
| `strtok` | 用静态变量保存状态，连续调用互相干扰 |
| `HAL_Delay` | 靠 SysTick 计数，而 SysTick 优先级低于当前中断时永远等不到——**永久卡死** |
| `HAL_UART_Transmit` | 阻塞式等待发送完成，如果中断优先级比串口高，会一直等 |

`HAL_Delay` 在 ISR 里卡死是新手最常见的坑。它的实现是"等 `uwTick` 变化到目标值"，而 `uwTick` 由 SysTick 中断累加。如果当前中断优先级高于 SysTick（默认就是），SysTick 永远进不来，`uwTick` 永远不变，函数永远不返回。

**ISR 里只调 `xxx_IT()` 版本、只置标志、只操作寄存器，其余统统放到主循环里做。** 这是唯一安全的写法。

## 4.7 中断上下文的三条铁律

1. **快**。ISR 执行时间直接决定中断延迟。1kHz 控制环要求 ISR 在几微秒内结束。重活全部丢给主循环（置标志 + 状态机）
2. **不阻塞**。不能 `while` 等硬件、不能 `delay`、不能 `printf`、不能 `malloc`
3. **不递归**。ISR 不能被自己重入（同优先级不会重入，但配置不当会）

一个衡量标准：**如果一段代码在 ISR 里执行超过 10 微秒，就值得重新设计。** 飞控里这句话是硬要求。

## 4.8 这一章要带走的东西

1. `volatile` 保证可见性，不保证原子性，也不保证顺序
2. Cortex-M 上对齐的单次 `uint32_t`/`uint8_t` 读写是原子的，64 位不是
3. `i++` 是三条指令，中断能插在中间，`volatile` 救不了
4. 临界区要"保存并恢复 PRIMASK"，而不是无条件 `__enable_irq()`
5. 临界区越短越好，里面不调函数、不做拷贝、不用浮点
6. 单写者模式能让大部分共享变量免保护，环形缓冲区就靠它
7. 跨执行环境传数据，要同时考虑可见性、顺序（`__DMB()`）、完整性
8. ISR 里不能调 `HAL_Delay`（会永久卡死）、`printf`、`malloc`
9. ISR 超过 10 微秒就该重新设计
