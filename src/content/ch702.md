# 第二章 时钟树：芯片的每一拍从哪来

[[anim:clock-tree]]

`HAL_RCC_ClockConfig()` 一行代码就把主频拉到 72 MHz，但它背后是一条由振荡器、倍频器、分频器组成的完整链路。这一章沿这条链从晶振走到外设：SYSCLK 为什么是 72 而不是 73、APB1 为什么最多 36 MHz、`__HAL_RCC_GPIOA_CLK_ENABLE()` 到底使能了什么。理解时钟树，你才能解释"为什么定时器算出来的周期不对""为什么低速外设跑不上主频"这些高频问题。

## 2.1 五个时钟源：两快两慢一专

F103 有五个时钟源，先记住两个常用的：

- **HSI**：内部 8 MHz RC 振荡器，无需外部器件，上电默认可用。缺点是精度差（±1%），USB 等对时钟精度敏感的外设用不了。
- **HSE**：外部晶振（常见 8 MHz），精度高（±20 ppm 量级），PLL 的标准输入。

另有三个特殊用途：**LSI**（约 40 kHz，喂独立看门狗与 RTC）、**LSE**（32.768 kHz 晶振，专供 RTC 走秒）、**PLL**（锁相环，不是独立源而是"倍频器"，输入只能选 HSI/2 或 HSE）。

$$f_{PLLout} = f_{in} \times \frac{N}{P} \qquad \text{（F103 简化为 } f_{in} \times N\text{）}$$

F103 的 PLL 倍频系数是 2~16 的整数。8 MHz 晶振 × 9 = 72 MHz，正好卡在最高主频上——**这就是"8 MHz 晶振是 F103 标配"的由来**：数字 9 是 PLLMUL 支持的值，72 是芯片极限。

## 2.2 从 SYSCLK 到外设：三级分频

PLL 输出成为 SYSCLK 候选，经过 AHB 预分频（HPRE）得到 HCLK，再向下分给两条外设总线：

$$f_{HCLK} = \frac{f_{SYSCLK}}{\text{HPRE}}， \quad f_{PCLK1} = \frac{f_{HCLK}}{\text{PPRE1}}， \quad f_{PCLK2} = \frac{f_{HCLK}}{\text{PPRE2}}$$

72 MHz 系统下的标准配置：AHB /1 → HCLK 72 MHz；APB1 /2 → 36 MHz（**硬件上限就是 36，挂 GPIOA~E 之外的低速外设**：USART2~5、SPI2、I2C、TIM2~4）；APB2 /1 → 72 MHz（高速区：GPIO、USART1、SPI1、ADC、TIM1）。

两个最容易算错的联动规则：

1. **APB 分频 ≠ 1 时，挂在该总线的定时器时钟自动 ×2**。APB1 = 36 MHz，但 TIM2 的计数时钟是 72 MHz——设计意图是让定时器永远能吃到高速时钟。所以算 PSC/ARR 时，"定时器时钟" ≠ "所在总线时钟"，要看分频是否为 1。
2. **ADC 的预分频是独立的**：ADCCLK 最大 14 MHz，从 72 MHz 分出来只能选 /2、/4、/6……/8 得 9 MHz，/6 得 12 MHz。很多"ADC 采样值抖"的问题，根源是选了超频档。

$$T_{timer} = \frac{(PSC+1)(ARR+1)}{f_{TIM}}$$

拿这条公式验证一次：f_TIM = 72 MHz、PSC = 7199、ARR = 9999，得 T = 7200 × 10000 / 72 000 000 = 1 s。如果误把 f_TIM 当成 36 MHz，配置出的周期会差一倍。

## 2.3 时钟门控：外设的"总开关"

RCC 的 AHB1ENR/APB1ENR/APB2ENR 每一位控制一个外设的时钟门。`__HAL_RCC_GPIOA_CLK_ENABLE()` 展开就一行：

```c
RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;
```

**时钟没开的外设，寄存器读出来全是 0，写进去什么也不发生**——不是"配置失败"，是物理上断供。所以任何外设初始化的第一步都是开时钟，忘开的典型症状是"写配置寄存器后回读永远为 0"。

还有一个反直觉的细节：**开时钟后要立刻加一小段延时或读回操作**（HAL 里是 `while(!(RCC->CR & ...))` 等待稳定位；开 GPIO 时钟后 HAL 会 dummy-read 一次 ENR）。因为门控开到外设真正收到第一拍时钟之间有几纳秒的建立时间，紧跟着的寄存器写入可能丢失。

## 2.4 改频率的完整步骤与安全顺序

把主频从默认 8 MHz 配到 72 MHz，正确顺序是**"先升后降"**：

1. 打开 HSE，`while(!HSERDY)` 等稳定；
2. 设置 Flash 等待周期（72 MHz 需 **2 个等待周期 WS=2**——闪存访问速度跟不上主频，必须插等待）；
3. 配 PLL：源选 HSE，倍频 ×9；
4. **使能 PLL，`while(!PLLRDY)`**；
5. 切换 SW 指向 PLL，`while(SWS != PLL)` 确认切换完成；
6. 配 HPRE=/1、PPRE1=/2、PPRE2=/1。

顺序错的典型后果：先切 SYSCLK 到 PLL 再配 Flash 等待周期 → CPU 跑到 72 MHz 了闪存还是 0 等待 → 取指不稳，HardFault 或跑飞。**HAL 的 `SystemClock_Config` 已经把顺序写对，但自己移植裸机代码时这是必踩的坑**。

另外两处安全细节：切换 SYSCLK 期间，SW/SWS 两位要轮询确认；改 AHB 分频后，部分外设（如 SDIO、FSMC）的时钟要重新核算。

## 2.5 验证频率的三个方法

配置对不对，用事实说话：

1. **MCO 引脚输出**：把 SYSCLK/2 或 HSE 引到 PA8（MCO），示波器量频率。这是最硬的证据。
2. **Systick 反推**：`HAL_InitTick` 里 `SystemCoreClock` 是全局变量，改完时钟后若忘了更新它（`SystemCoreClockUpdate()`），延时函数全部等比例错。
3. **DWT 周期计数器**：`DWT->CYCCNT` 在已知延时前后读差值，除以主频即真实时间，不用示波器也能验证。

## 2.6 五个经典坑

1. **忘开外设时钟**：症状"寄存器写不进去"。第一反查 RCC 各 ENR 对应位。
2. **定时器用了总线频率而非定时器频率**：APB 分频 ≠ 1 时定时器时钟 ×2。所有"周期差一倍"的问题先查这个。
3. **HSI 起家忘了切 HSE**：串口波特率误差 ±1% 恰好压线，偶发乱码。涉及 USB/精确波特率一律 HSE + PLL。
4. **LSE 不起振**：32.768 kHz 晶振负载电容配错（应 6~12 pF），RTC 走时飞快或完全停摆。`LSERDY` 等待要加超时，否则没焊晶振的板子会卡死在等待循环。
5. **SystemCoreClock 变量没同步**：改完 RCC 不调 `SystemCoreClockUpdate()`，HAL_Delay、波特率计算全部按旧频率算。

## 2.7 本章小结

- 五个源：**HSI/HSE 是主力，LSI/LSE 供低功耗时钟，PLL 只做倍频**。
- 三级分频：**SYSCLK → AHB(HPRE) → APB1/APB2(PPRE)**，APB 分频 ≠1 时定时器自动 ×2。
- **时钟门控是外设总开关**，没开时钟 = 寄存器物理断供。
- 升频顺序：**HSE → Flash 等待 → PLL → 切换 SYSCLK**，任何一步顺序颠倒都可能 HardFault。
- 验证三法：**MCO 输出、SystemCoreClock 反推、DWT 周期计数**。

时钟解决了"多快地跑"，下一章解决"事件来了怎么响应"——中断的硬件真相。
