# 第四章 内存布局：你的变量住在哪

[[anim:mem-layout]]

`uint8_t buf[1024];` 写下这行代码时，它就注定要去 RAM 的某个位置——但具体在哪、谁决定的、和堆栈怎么相处，很多人答不上来。这一章把 32 KB SRAM 切开给你看：每一段叫什么名字、链接脚本怎么描述它们、MAP 文件怎么核对，最后演示栈是怎么把堆撞穿而编译器一声不吭的。

## 4.1 五段式内存地图

一个 C 程序在 SRAM 里的经典布局，从低地址到高地址：

```text
0x2000_0000  ┌──────────────────────┐ 低地址
             │ .data   已初始化全局   │ ← 启动时从闪存搬来
             ├──────────────────────┤
             │ .bss    零初始化全局   │ ← 启动时清零
             ├──────────────────────┤
             │ heap    向上增长 →     │ ← malloc 的领地
             ├──────────────────────┤
             │      （空闲间隙）      │
             ├──────────────────────┤
             │ stack   ← 向下增长     │ ← 局部变量、调用帧
             ├──────────────────────┤
0x2000_8000  └──────────────────────┘ 高地址（MSP 初值）
```

闪存一侧也有对应分段：`.isr_vector`（向量表，必须放最前）→ `.text`（代码）→ `.rodata`（const 常量与字符串字面量）→ `.data_init`（`.data` 的初始值副本）。

**堆和栈相向而行**，中间的空闲区就是安全余量。两者一撞，就是最难查的内存踩踏。

## 4.2 每个变量去哪：编译器的分配规则

| 声明 | 去处 | 原因 |
| --- | --- | --- |
| `int g = 5;` | `.data`（RAM）+ 初始值进闪存 | 可写，且要保初值 |
| `int g;` | `.bss` | 可写，初值 0 |
| `const int t[100] = {...}` | `.rodata`（闪存） | 只读，不值得占 RAM |
| `static int s;` | 与普通全局相同 | static 只影响可见性，不影响存储 |
| `int x;`（函数内） | 栈 | 局部变量由 SP 相对寻址 |
| `char *p = malloc(n);` | p 在栈/全局，n 字节在堆 | 运行期分配 |
| `const char *s = "abc";` | 指针本身按位置，"abc" 进 `.rodata` | 字面量只读 |

两个反直觉的点：**`const` 局部变量仍在栈上**（const 是语义约束，不是存储指令）；**`static` 局部变量在 `.data/.bss`**（生命周期等同全局）。一张表记住：**决定去处的只有三件事——生命周期（全局/局部）、可写性（const 与否）、初始化方式（是否带非零初值）**。

## 4.3 链接脚本：内存地图的法律文本

`.ld` 文件（GCC）用两段描述一切。**MEMORY** 声明物理区域：

```ld
MEMORY
{
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 128K
  RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 20K
}
```

**SECTIONS** 把输入段归堆：

```ld
.data : { _sdata = .; *(.data*) _edata = .; } > RAM AT> FLASH
.bss  : { _sbss = .;  *(.bss*)  _ebss = .;  } > RAM
```

`> RAM AT> FLASH` 这一句就是 `.data` "住在 RAM、初始值存闪存"的法律依据，第一章启动代码里那三个 `_sidata/_sdata/_edata` 符号，全是这里 `= .` 赋出来的。**改链接脚本 = 改内存地图**：加大堆（`_estack` 下移）、加 `NOLOAD` 段、放自定义段（如把某数组钉进特定地址），都在这里动手。

需要绝对地址的外设缓冲区（如 DMA 不能碰的区域）可以这样钉：

```c
__attribute__((section(".ccmram"), aligned(32))) uint8_t adc_buf[512];
```

## 4.4 MAP 文件核对：纸上谈兵三分钟

链接产物 `.map` 的 Symbol Table 把每个变量列得清清楚楚：

```text
g_init        0x20000000   Data           4  main.o(.data)
g_count       0x20000004   Data           4  main.o(.bss)
adc_buf       0x20000008   Data         512  adc.o(.bss)
heap_start    0x20000208   Data           0  startup.o(HEAP)
__initial_sp  0x20005000   Data           0  startup.o(STACK)
```

核对三件事：**RAM 总占用**（最后一个变量 + 栈深是否超出 20 KB）、**意外的大数组**（哪个文件贡献的 `.bss` 最大）、**栈顶值**（是否等于 RAM 物理末尾）。ROM/RAM 尺寸超限时报错也来自这里——链接器按 MEMORY 声明检查。

## 4.5 栈撞堆：一场无声的车祸

栈溢出的可怕在于**编译器完全不管**。演示一次车祸全程：

```c
uint8_t *heap_p = malloc(1024);        /* 堆占 0x2000_0208 ~ 0x2000_0608 */

void deep(int n) {
    uint8_t frame[256];                /* 每层递归吃 256 字节栈 */
    if (n < 40) deep(n + 1);           /* 40 层 = 10240 字节 */
}
```

栈从 `0x2000_5000` 向下长 10 240 字节 → 到 `0x2000_2A00`。堆顶在 `0x2000_0608`——还没撞上。递归改 56 层：栈到达 `0x2000_0600`，**正好扎进堆里**。之后 `deep()` 每写一个 `frame`，就踩坏一处堆数据。症状：`malloc` 返回的缓冲区"莫名其妙被改写"，而你的代码从没碰过它。

三种防线（全都要上）：

1. **静态核算**：MAP 里最深的调用链 × 每帧大小 + ISR 最坏嵌套 ≈ 栈需求，RAM 里留 30% 余量。
2. **运行时水印**：上电把栈区涂满 `0xA5`，跑够业务后扫到最高的非 A5 位置即"水位线"，FreeRTOS 的 `uxTaskGetStackHighWaterMark` 就是这个原理。
3. **MPU 划保护区**：在栈底下方设一个不可访问区，越界立刻 Fault，把无声车祸变成有声报警。

$$\text{RAM 余量} = S_{RAM} - (|\text{.data}| + |\text{.bss}| + \text{heap}_{max} + \text{stack}_{max}) \ge 30\% \cdot S_{RAM}$$

## 4.6 五个经典坑

1. **大缓冲区定义在函数里**：`uint8_t buf[4096];` 写在函数内就是 4 KB 栈需求，一调用就爆。改 `static` 或挪到全局。
2. **`sprintf`/`printf` 首次调用的隐式栈峰**：C 库格式化函数内部要 1~2 KB 栈，平时测不出的溢出可能在第一次打印日志时爆发。
3. **ISR 嵌套的栈账没算**：每嵌套一层至少 32 字节（8 个自动压栈 + 局部变量），8 层嵌套的优先级设计会放大栈需求。
4. **memcpy 长度笔误**：把 `sizeof(src)` 写成 `sizeof(dst)` 之类，越界写到哪个段全凭运气——MAP 文件能告诉你它踩了谁。
5. **heap 定义了不用**：不用 malloc 就把堆设 0（GCC 下改 `_Min_Heap_Size`），把空间还给栈。

## 4.7 本章小结

- SRAM 五段：**.data / .bss / heap / 空闲 / stack**，堆栈相向增长。
- 变量去哪由**生命周期 + 可写性 + 初值**三件事决定；`const` 局部量仍在栈上，`static` 局部量在 `.data/.bss`。
- **链接脚本是内存地图的法律文本**，`.data` 的"住 RAM、存闪存"就是 `>RAM AT>FLASH` 一句话。
- **MAP 文件三查**：总占用、大数组、栈顶值。
- 栈撞堆编译器不管——**静态核算 + 水位线 + MPU 三道防线**。
