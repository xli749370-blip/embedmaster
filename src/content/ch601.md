# 第一章 项目立项与系统架构：从需求到框图

> 前面五门课把「点」都讲透了，这一门把它们连成「线」：做一个能上电、能测、能上报、能低功耗运行的温湿度无线传感器节点。

## 1.1 需求拆解

先把模糊的想法变成可验收的指标，否则后面每一步都会返工：

| 维度 | 需求 | 量化指标 |
| --- | --- | --- |
| 功能 | 采集环境温湿度 | 温度 ±0.3 ℃、湿度 ±2 %RH |
| 连接 | 手机能读到数据 | 蓝牙 BLE 4.2 以上，10 m 内稳定 |
| 供电 | 电池供电 | 单节 Li 电池或 2×AA，续航 ≥ 3 个月 |
| 体积 | 可贴在墙面 | PCB ≤ 50×35 mm |
| 成本 | 可量产 | 物料 BOM < 25 元 |

> 工程经验：需求里最容易被忽略的是**续航**和**成本**。很多学生项目做到能跑就停了，但"能跑一个月"和"能跑三个月"在电路设计上是两回事。

## 1.2 模块划分

把整机拆成五个最小功能块，每块只干一件事：

```
        ┌─────────────┐
        │  电源模块    │  Li 电池 → LDO → 3.3V
        │ (电池+充电)  │
        └──────┬──────┘
               │ 3.3V
   ┌───────────┼───────────────────────────┐
   │           │                            │
┌──▼───┐   ┌──▼────┐   ┌────────┐   ┌──────▼─────┐
│ SHT30│   │ STM32 │   │ 蓝色LED│   │ 蓝牙模块   │
│ 温湿度│──I2C──▶│ 主控  │   │ 指示  │   │ (BLE 透传) │
│ 传感器│   │      │◀──PWM──│       │◀──UART─────│
└──────┘   │      │   └────────┘   └────────────┘
           │      │
           │      │──ADC──▶ 电池电压分压检测
           └──────┘
```

- **传感**：SHT30，I2C 接口，精度远高于 DHT11，且无需上电等待。
- **主控**：STM32（F1 或 L0 系列），跑 FreeRTOS，负责采集、打包、调度。
- **无线**：蓝牙模块（如 JDY-08 / 汇承 HC-08 类），串口透传，手机小程序直接读。
- **电源**：电池 + 低压差线性稳压器（LDO），省去复杂电源管理。
- **指示**：一颗 LED 做状态/低电量提示，PWM 呼吸效果。

## 1.3 技术选型与取舍

为什么不用 ESP32？为什么不用 ZigBee？选型要讲得出理由：

| 候选 | 优点 | 落选原因（本项目） |
| --- | --- | --- |
| ESP32 | 自带 Wi-Fi/蓝牙、算力强 | 功耗高，电池续航撑不住 3 个月 |
| nRF52 | 超低功耗 BLE 原生 | 需要专用工具链，生态门槛高 |
| STM32 + 透传模块 | 复用前几章知识、调试简单 | 体积略大，但本项目可接受 |

> 结论：**STM32 + 串口蓝牙透传模块**是最契合"把已学知识用起来"的方案。主控用 STM32F103C8T6（或更低功耗的 STM32L031），蓝牙用串口 AT 指令类模块。

## 1.4 功耗预算

续航是设计约束，不是事后补救。先算理论值：

$$I_{avg} = I_{active} \times D + I_{sleep} \times (1 - D)$$

其中占空比 $D = T_{active} / (T_{active} + T_{sleep})$。假设每 10 分钟唤醒一次，唤醒工作 200 ms：

- 工作时电流 $I_{active} \approx 8\,\text{mA}$
- 睡眠时电流 $I_{sleep} \approx 12\,\mu\text{A}$（主控 STOP + 模块休眠）
- $D \approx 200\,\text{ms} / 600\,\text{s} \approx 3.3\times10^{-4}$

$$I_{avg} \approx 8\,\text{mA} \times 3.3\times10^{-4} + 12\,\mu\text{A} \times 0.9997 \approx 14.6\,\mu\text{A}$$

一节 2000 mAh 的 18650，理论续航 $\approx 2000 / 0.0146 \approx 13.7$ 万小时 ≈ **15 年**——显然不现实，因为蓝牙模块待机、LDO 静态电流、自放电会吃掉大头。实际按 **3~6 个月** 规划更稳。

## 1.5 通信帧的雏形

手机要能解析数据，双方必须先约定格式。先定一个最小帧：

```
| 0xAA | 0x55 | LEN | CMD | PAYLOAD... | CRC16 |
  帧头   帧头   长度  命令   数据体      校验
```

- 帧头固定 `AA 55`，用于接收端在字节流里"找头"。
- `LEN` 是 PAYLOAD 字节数，便于处理粘包。
- `CRC16` 覆盖从 LEN 到 PAYLOAD 的全部字节，挡掉误码。

具体实现留到第五章。这里先建立"**协议是双方的契约**"这个意识。

## 1.6 开发里程碑

把大任务切成可交付的小步，每步都能验收：

1. 电源树跑通：不焊 MCU，先量 3.3 V 稳不稳
2. MCU 最小系统：SWD 能连、点灯成功
3. I2C 读出 SHT30：串口打印温湿度
4. 蓝牙透传：手机收到 MCU 发的字符串
5. 加上 RTOS：采集/上报/指示三任务并行
6. 低功耗：进 STOP，测平均电流
7. 协议封装：自定义帧 + CRC，手机解析

> 原则：**每完成一步就固化一次**。不要等到"全部写完"再上电，那样任何一个 bug 都难以定位。

## 本章要点

- 需求先量化（精度/续航/成本/体积），再谈方案
- 模块划分：传感 / 主控 / 无线 / 电源 / 指示，各司其职
- 选型要讲理由，本项目选 STM32 + 串口蓝牙透传
- 续航由占空比决定，先算 $I_{avg}$ 再定电池
- 协议是契约：帧头 + 长度 + 命令 + 载荷 + CRC
- 里程碑式开发，每一步都可验收

完成本章后，请前往「在线刷题」做一次自测，确认系统架构与功耗公式能独立推导。
