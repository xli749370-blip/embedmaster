# 第一章 从上电到 main：启动全流程

[[anim:boot-timeline]]

你写的第一行 C 代码是 `main` 里的 `HAL_Init()`。但在它执行之前，芯片已经默默做完了十几件事：读取向量表、设置栈指针、把已初始化的全局变量从闪存搬到 RAM、把未初始化的全局变量清零、配置时钟、重定位向量表……这一章把这条链完整拆开。理解启动流程之后，你会明白为什么变量要初始化、`.data` 和 `.bss` 到底是谁在管、为什么栈顶指针要放在镜像的最前面——后面所有"玄学 bug"都会变得有迹可循。

## 1.1 复位之后的第一条指令：硬件只做三件事

按下复位（或上电）的瞬间，Cortex-M 内核只做三件事，其余全靠软件：

1. **从地址 `0x0000_0000` 读出 4 字节，作为主栈指针 MSP 的初值**；
2. **从地址 `0x0000_0004` 读出 4 字节，作为 PC（程序计数器）的初值**——这就是复位向量；
3. 从这个 PC 开始执行指令。

没有别的了。C 语言运行环境（栈可用、全局变量有值）硬件一概不管，全靠前几行代码自己搭。

通常 STM32 的闪存映射在 `0x0800_0000`，但启动时芯片会把它镜像到 `0x0000_0000`（取决于 BOOT 引脚的配置）。所以向量表实际烧在闪存开头，内核读 `0x0000_0000` 就是读闪存第一个字。

向量表的前两个字的含义是**强约定**：

$$\text{MSP}_{init} = \text{mem}[0x00000000], \qquad \text{PC}_{reset} = \text{mem}[0x00000004]$$

对应启动文件（`startup_stm32f103xb.s`）里最开头的两张表：

```asm
__Vectors       DCD     __initial_sp          ; 栈顶指针 → 0x0800_0000 处的第一个字
                DCD     Reset_Handler         ; 复位向量 → 0x0800_0004
                DCD     NMI_Handler
                DCD     HardFault_Handler
                ...
```

`__initial_sp` 是链接器算出来的符号，等于 RAM 末尾（栈从高处往低处长，所以栈顶初值是 RAM 的最上沿）。**这就是为什么"栈顶地址必须是向量表第一个字"——硬件不认识 C，它只会取这个数塞进 MSP**。

一个常见误区：很多人以为上电后内核会"初始化"寄存器。实际上除了 MSP 和 PC，其他寄存器的值要么为 0 要么不定，LR 一开始也是未知值。所以 `Reset_Handler` 必须先做可靠性建设，才能跳进 C 世界。

## 1.2 Reset_Handler：C 世界前的最后四件事

复位向量指向的第一段代码叫 `Reset_Handler`，它不是 HAL 写的，也不是你写的，而是启动文件里的一段汇编。它要赶在进入 C 之前完成四件事：

**第一件：把 `.data` 段从闪存复制到 RAM。**

已初始化的全局变量（比如 `int baud = 115200;`）的**初始值**必须掉电不丢，所以烧在闪存里；但变量本身又要能被改写，必须住在 RAM 里。于是编译器把"初始值"打包成 `.data` 段放闪存，启动时由代码搬到 RAM。这一步是 `memcpy(ram_start, flash_start, size)` 的裸写法：

```c
extern uint32_t _sidata;  /* .data 在闪存中的起始地址（装载域） */
extern uint32_t _sdata;   /* .data 在 RAM 中的起始地址（运行域） */
extern uint32_t _edata;   /* .data 在 RAM 中的结束地址 */

for (uint32_t *s = &_sidata, *d = &_sdata; d < &_edata; )
    *d++ = *s++;
```

这三个下划线符号都是链接脚本定义的。如果你在 MAP 文件里搜 `_sidata`，会发现它紧挨着 `.text` 段的末尾——**`.data` 的初始值就是嵌在闪存里的字节数组，启动代码负责"解压"**。

**第二件：把 `.bss` 段清零。**

未初始化的全局变量（`int count;`）和显式零初始化（`int zero = 0;`）都住在 `.bss`。C 标准要求它们必须等于 0，而 RAM 上电是什么值并不保证，所以也要靠启动代码：

```c
extern uint32_t _sbss, _ebss;
for (uint32_t *d = &_sbss; d < &_ebss; ) *d++ = 0;
```

这也是"全局变量不用初始化就默认是 0"的底层真相——**不是编译器给的，是启动代码逐字清出来的**。局部变量没有这个待遇，所以局部变量不初始化就是垃圾值。

**第三件：调用 `SystemInit()`。**

这一步配好时钟（默认 HSI）、清复位标志、把向量表寄存器 VTOR 指到闪存开头。在 HAL 工程里它做得很轻，真正的时钟大配置留给 `SystemClock_Config()`——这也是为什么上电后前几毫秒跑的是 8 MHz 的 HSI 而不是 72 MHz。

**第四件：跳进 `main()`。**

在 ARM 编译器下是跳到 `__main`（C 库的初始化入口，它再调 main）；GCC 下 `Reset_Handler` 末尾直接一句 `bl main`。从此进入你的世界。

$$\text{启动耗时} \approx t_{vector} + \frac{4 \cdot N_{data} + 4 \cdot N_{bss}}{f_{bus}} + t_{SystemInit}$$

`.data` 越大启动越慢。曾经有人在 `.c` 里写了个 64 KB 的大数组做查找表且带初始值，启动时间直接多出十几毫秒——改成 `const`（进 `.rodata`，留在闪存不搬运）立刻恢复。

## 1.3 向量表：中断号的索引数组

向量表不只有前两个字。从 `0x0000_0000` 开始，每 4 字节一个表项，依次是 MSP、Reset、NMI、HardFault……一直到所有外设中断。**表项里存的不是"地址常量"，而是函数指针**——内核响应中断时，硬件自动从这个数组取出对应项塞进 PC。

所以中断函数名不是随便起的：你在启动文件里看到 `USART1_IRQHandler`，意味着向量表第 53 项填的就是这个名字，你的 C 函数必须用**完全相同的名字**才能被链接器正确填表。名字打错一个字母，链接器不会报错，只是把默认的死循环 `Default_Handler` 填进去——表现为"中断一来就卡死"。

向量表位置由 VTOR 寄存器决定。上电默认指向 `0x0000_0000`，如果你把代码搬到 RAM 跑、或者用 IAP 升级让 App 在 `0x0800_3000`，就必须重设：

```c
SCB->VTOR = 0x08003000;   /* 之后所有中断都从新表取地址 */
```

 bootloader 类程序（IAP、固件升级）最容易在这翻车：跳转前忘了关中断 + 忘了改 VTOR，结果 App 里一开中断，硬件还是去 bootloader 的旧表里取函数地址——直接跳回 bootloader 的中断处理，看似"重启"，实为走错门。

## 1.4 用 MAP 文件核对一切

链接器生成的 `.map` 文件是启动过程的"账本"，务必学会看三处：

- **`Memory Map of the image`**：各段的装载地址（闪存）与运行地址（RAM）。`.data` 会同时出现两列地址，这就是"装载域 vs 运行域"。
- **`Image Symbol Table`**：`_sidata`、`_sdata`、`_edata`、`_sbss`、`_ebss`、`__initial_sp` 的值。全局变量逐个列出，各属哪一段一目了然。
- **总尺寸**：`Total RO Size`（闪存占用）与 `Total RW Size`（RAM 占用）。RAM 里 RW + ZI 就是 `.data + .bss`，栈和堆还要另算——**链接器不检查栈溢出，RAM 尺寸要自己留够**。

```text
.data   0x20000000   Load 0x08001a40   0x48    ; 72 字节已初始化变量
.bss    0x20000048   Runtime           0x1c0    ; 448 字节零初始化变量
heap    0x20000208                         0x400   ; 堆起点
stack   0x20002000   __initial_sp               ; 栈顶 = RAM 末尾
```

像上面这样，堆和栈之间留了多少空间，直接决定你能 `malloc` 多少、递归能多深。

## 1.5 五个经典坑与排查方法

1. **中断函数名拼错**：向量表填的是 `Default_Handler` 死循环。现象是"一开中断就假死"。排查：在 MAP 里搜你的函数名，确认它真的出现在向量表里。
2. **`.data` 过大拖慢启动**：大数组加 `const` 进 `.rodata`；确实要可写的，评估是否运行时生成。
3. **全局构造依赖顺序**：在另一个全局变量的初始化里调用函数、访问别的全局变量——`.bss` 清零顺序无所谓，但 C++ 全局构造、带函数调用的初始化可能在时钟未配好时执行，拿到错误频率。
4. **IAP 跳转三件套没做齐**：跳转前关所有中断、清 pending、`SCB->VTOR = app_base`、`__set_MSP(app[0])`、跳 `app[1]`。少一件都是"偶发重启"。
5. **栈顶指针没对齐到 8 字节**：AAPCS 要求调用约定 8 字节对齐。链接器通常保证，但手工改链接脚本后要复查，否则进 C 后第一条 `bl` 就可能出 HardFault。

## 1.6 本章小结

- 复位后硬件只做两件事：从 `0x0000_0000` 取 **MSP 初值**、从 `0x0000_0004` 取 **复位向量**。
- `Reset_Handler` 的三件套：**搬 `.data`、清 `.bss`、调 `SystemInit`**，然后才进 `main`。
- 全局变量默认为 0 是**启动代码清出来的**，局部变量没有这份保障。
- 向量表本质是**函数指针数组**，中断函数名必须与启动文件一致；换运行地址必须同步改 **VTOR**。
- **MAP 文件**是核对内存布局的第一手资料，`.data/.bss/heap/stack` 的位置与大小都能查到。

启动流程是"静态的账"，下一章看"动态的脉"：这些模块到底用哪路时钟、频率怎么来——时钟树。
