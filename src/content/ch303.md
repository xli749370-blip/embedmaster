# 第三章 定时器与 PWM：把时间变成波形

> 定时器是 STM32 里最"不像外设"的外设。串口、SPI 只是把数据搬进搬出，定时器却能凭空产生时间基准、生成任意波形、统计脉冲个数、测量信号宽度。一块芯片能不能做控制，看的就是定时器够不够用。

## 3.1 时基单元：三个寄存器的协同

一个通用定时器的核心是三个寄存器组成的一条链路：

```
时钟源 (72MHz)
    ↓
[PSC 预分频器]  每 (PSC+1) 个时钟产生一次计数脉冲
    ↓
[CNT 计数器]    在 0 ~ ARR 之间循环计数
    ↓
[ARR 自动重装载] 计数到 ARR 时归零，产生更新事件
```

三个参数的准确定义：

| 寄存器 | 作用 | 实际除数 / 周期 |
|---|---|---|
| `PSC`（预分频） | 把高频时钟降下来 | 分频系数 = **PSC + 1** |
| `ARR`（自动重装） | 决定计数到多少归零 | 周期 = **ARR + 1** 个计数 |
| `CNT`（计数器） | 当前计数值 | 0 ~ ARR |

**两个 "+1" 是新手最常算错的地方。** 因为寄存器从 0 开始计数，`PSC = 0` 表示不分频（÷1），`ARR = 0` 表示每 1 个计数就溢出一次。

### 频率与周期的计算

定时器溢出频率（也就是 PWM 频率）：

$$
f_{out} = \frac{f_{clk}}{(PSC+1) \times (ARR+1)}
$$

反过来，想得到指定频率：

$$
ARR+1 = \frac{f_{clk}}{(PSC+1) \times f_{out}}
$$

举例：系统时钟 72MHz，要产生 1kHz 的 PWM，并希望有 1000 级占空比分辨率。

先定分频：取 `PSC = 71`，把计数时钟降到

$$
f_{cnt} = \frac{72\text{MHz}}{72} = 1\text{MHz}
$$

即每个计数 = 1μs。然后 1kHz 周期是 1ms = 1000μs，所以

$$
ARR+1 = 1000 \Rightarrow ARR = 999
$$

这样 CCR 从 0 到 1000，每改变 1 就是 0.1% 的占空比变化，分辨率刚好 1000 级。

**把上面的算式搬到画布上。** 动画上方那排密集的橙色细线就是 72MHz 的时钟，
每个计数周期内有多少根线，就代表 `PSC+1` 是多少：切到 `PSC=71` 时一个周期里塞进 72 个时钟，
而 `PSC=0` 时一个时钟就是一个计数。中间那条蓝色方波是分频后的计数脉冲，
每来一个上升沿 `CNT` 加一，加到 `ARR` 就归零并产生一次更新事件（UEV）。

值得对比的是「1 kHz · 100 级」和「1 kHz · 1000 级」这两个预设：**溢出频率完全一样，
但 `ARR+1` 差了十倍**。前者占空比只能调 100 档（1% 一步），后者能调 1000 档（0.1% 一步）。
这就是「同样 1kHz，为什么别人调光更细腻」的答案——分辨率是被 `ARR` 买来的，
而抬高 `ARR` 就必须压低 `PSC`，两者此消彼长，乘积才决定频率。

## 3.2 占空比：比较寄存器 CCR

PWM 模式下，计数器 `CNT` 与比较寄存器 `CCR` 不断比较：

- **PWM 模式 1**：`CNT < CCR` 时输出高电平，`CNT ≥ CCR` 时输出低电平
- **PWM 模式 2**：与模式 1 相反

所以占空比：

$$
\text{Duty} = \frac{CCR}{ARR+1} \times 100\%
$$

平均电压（对负载而言）：

$$
V_{avg} = V_{CC} \times \frac{CCR}{ARR+1}
$$

这条公式是所有 PWM 应用的基石：**用开关的方式等效出任意中间电压**。LED 调光、电机调速、DAC 输出，本质都是它。

## 3.3 频率与分辨率的取舍

这是配 PWM 时必须先想清楚的一件事：**在固定时钟下，频率和分辨率成反比。**

$$
\text{分辨率} = \frac{f_{clk}}{(PSC+1) \times f_{out}}
$$

意思是在 72MHz 下：

| PWM 频率 | 最大分辨率 | 每级步进 |
|---|---|---|
| 1 kHz | 72000 级 | 0.0014% |
| 10 kHz | 7200 级 | 0.014% |
| 20 kHz | 3600 级 | 0.028% |
| 50 kHz | 1440 级 | 0.07% |

不同应用对这两者的要求完全不同：

- **LED 调光**：人眼对 100Hz 以上不闪烁，频率取 1–5kHz 足够，剩下的全给分辨率。如果用 8 位分辨率（256 级），低亮度区会出现明显跳变。
- **直流电机调速**：频率要高于人耳听觉范围（>20kHz），否则电机会啸叫。20kHz 下 3600 级分辨率仍然够用。
- **舵机**：标准模拟舵机只认 50Hz（周期 20ms），这是硬性规定，不能改。分辨率需求也不高（角度精度约 1°）。
- **音频输出**：需要 >40kHz 且高分辨率，通常直接用专用 DAC 或 I2S。

## 3.4 舵机控制：一个必须算准的例子

标准舵机的信号规范：

- 周期 **20ms**（50Hz）
- 高电平宽度 **0.5ms** 对应 0°，**2.5ms** 对应 180°
- 中间 1.5ms 对应 90°

配置步骤：

1. 让计数时钟 = 1μs：`PSC = 71`（72MHz ÷ 72 = 1MHz）
2. 周期 20ms = 20000μs：`ARR = 19999`
3. 角度到 CCR 的映射：

$$
CCR = 500 + \frac{\theta}{180} \times 2000
$$

验证：$\theta = 0$ → CCR = 500 → 0.5ms；$\theta = 90$ → CCR = 1500 → 1.5ms；$\theta = 180$ → CCR = 2500 → 2.5ms。正确。

```c
/* 舵机角度设置（0~180 度） */
void Servo_SetAngle(TIM_HandleTypeDef *htim, uint32_t ch, uint8_t angle)
{
    if (angle > 180) angle = 180;
    uint32_t ccr = 500 + (uint32_t)angle * 2000 / 180;
    __HAL_TIM_SET_COMPARE(htim, ch, ccr);
}
```

**注意用 `__HAL_TIM_SET_COMPARE` 而不是直接写 `CCR` 寄存器。** 宏内部做了通道判断，可读性更好；更重要的是在某些高级定时器上，直接写 CCR 可能因为预装载使能而延迟到下一个周期才生效。

## 3.5 死区时间：H 桥驱动的保命配置

驱动直流电机、无刷电机时，通常用 H 桥或三相逆变桥。每一相有上下两个开关管，理想情况下它们互补导通——上管开时下管必须关。

但真实器件有关断延迟。如果上管还没完全关断、下管就打开了，电源会通过两个管子直接短路到地，这叫**直通（shoot-through）**，瞬间电流可达几十安培，直接炸管。

**死区时间**就是在这两者切换之间插入的一段"上下都关"的空白期。STM32 的高级定时器（TIM1、TIM8）硬件支持死区插入：

```c
TIM_BreakDeadTimeConfigTypeDef bdt = {0};
bdt.DeadTime      = 72;          /* 72 个时钟周期，1MHz 下 = 72ns */
bdt.OffStateRunMode = TIM_OSSR_ENABLE;
bdt.OffStateIDLEMode = TIM_OSSI_ENABLE;
bdt.BreakState    = TIM_BREAK_ENABLE;
bdt.BreakPolarity = TIM_BREAKPOLARITY_HIGH;
bdt.AutomaticOutput = TIM_AUTOMATICOUTPUT_ENABLE;
HAL_TIMEx_ConfigBreakDeadTime(&htim1, &bdt);
```

死区时长要查 MOS 管的 datasheet，通常取关断时间 + 驱动电路延迟 + 50% 余量。太小起不到保护作用，太大会损失有效占空比、导致输出波形畸变。

**这也是为什么电机驱动必须用 TIM1/TIM8，而不是普通 TIM2/TIM3**——只有高级定时器有互补输出和死区硬件。

## 3.6 定时器的四种用法

除了 PWM，同一个定时器还能做这些事，值得了解全貌：

| 用法 | 原理 | 典型场景 |
|---|---|---|
| 时基中断 | 溢出时产生中断 | 任务调度、软件定时 |
| PWM 输出 | CNT 与 CCR 比较 | 调光、调速、舵机、DAC |
| 输入捕获 | 记录边沿到来时的 CNT 值 | 测频率、测脉宽、超声波测距 |
| 编码器模式 | 硬件自动解码 A/B 相 | 电机测速、旋钮 |

**编码器模式**特别值得一说：它是纯硬件解码，不需要任何中断。把编码器 A/B 相接到定时器的 CH1/CH2，配置成编码器模式，硬件自动根据相位关系增减 CNT。CPU 只需要定期读一次 CNT 就能得到位置和速度。手工用中断解码在两个边沿同时触发时会丢步，硬件方案不会。

## 3.7 五个高频踩坑

**坑一：ARR 和 PSC 差 1。**
算出来要 1kHz，代码里写 `ARR = 1000`，实际得到 999Hz 左右的偏差。频率要求严格时必须减 1。

**坑二：忘了开定时器。**
`HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1)` 必须调用，只配不启是不会有波形的。而且每个用到的通道都要单独 Start。

**坑三：引脚没配成复用。**
CubeMX 里选了 PWM 但忘了确认引脚模式，或者手写代码时把引脚配成了普通输出。此时 CCR 在变、波形出不来。

**坑四：改了 ARR 不产生更新事件。**
运行中修改 ARR，新的值要等到下一次溢出才生效。如果需要立即生效，要手动 `__HAL_TIM_SET_AUTORELOAD` 后调用 `HAL_TIM_GenerateEvent(&htim, TIM_EVENTSOURCE_UPDATE)`。

**坑五：PWM 频率落在音频段。**
电机驱动用了 8kHz，人耳听得到尖锐的啸叫。改到 20kHz 以上就消失了——这不是"故障"，是物理现象。

## 3.8 本章小结

- 时基 = `f_clk / ((PSC+1)(ARR+1))`，两个 +1 不能忘。
- 占空比 = `CCR / (ARR+1)`，平均电压 = `V_CC × 占空比`。
- 固定时钟下，频率与分辨率成反比，按应用需求取舍。
- 舵机是硬性 50Hz 规范，CCR 从 500 到 2500 对应 0–180°。
- 驱动 H 桥必须配死区，且只有 TIM1/TIM8 支持。
- 同一外设还能做输入捕获、编码器解码，全是硬件行为，不占 CPU。
