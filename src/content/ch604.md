# 第四章 RTOS 任务编排：让采集、上报、指示并行

> 裸机写法里，采集、上报、指示灯全挤在一个 `while(1)` 里顺序跑，彼此拖累。这一章用 FreeRTOS 把三者拆成独立任务，并通过队列/信号量解耦。

## 4.1 任务划分

把系统行为按"独立并发"原则拆成四个任务：

| 任务 | 周期 | 优先级 | 职责 |
| --- | --- | --- | --- |
| `sensor_task` | 每 10 s | 中 | 触发 SHT30 测量，读温湿度 |
| `report_task` | 事件驱动 | 高 | 把数据打包成帧，经 UART 发出 |
| `battery_task` | 每 60 s | 低 | 读电池电压，更新低电标志 |
| `led_task` | 事件驱动 | 低 | 根据状态机刷新 PWM 呼吸/闪烁 |

> 优先级反直觉提醒（来自 RTOS 课）：**数值小反而优先**。`report_task` 优先级高于 `sensor_task`，是因为数据一旦采到就应尽快发出，避免被后续采集阻塞。

## 4.2 任务间通信：队列传数据，信号量通知

`sensor_task` 采完数据，不能自己直接调 `ble_send`（那样又耦合回去了）。正确做法：

```
sensor_task -- 测量 --> 存入 Queue(data_q)
                              │
                      report_task 从队列取出
                              │
                          打包帧 --> ble_send
```

```c
QueueHandle_t data_q = xQueueCreate(4, sizeof(Sample_t));

// sensor_task 里：
Sample_t s = { .temp = t, .hum = h, .ts = xTaskGetTickCount() };
xQueueSend(data_q, &s, 0);

// report_task 里：
Sample_t s;
if (xQueueReceive(data_q, &s, portMAX_DELAY) == pdTRUE) {
    frame_build_and_send(&s);   // 解耦：report 不关心谁采的
}
```

- **队列**传递数据本身，发送方与接收方互不知道对方存在。
- 若只需"通知有事件发生"，用**二值信号量 / 直接任务通知**更轻量。

## 4.3 状态机：把行为收敛成有限状态

整机行为用状态机描述，避免 `while(1)` 里一堆 `if` 互相打架：

```
   [IDLE] --定时到--> [MEASURE] --采完--> [REPORT]
     ▲                  │                  │
     │                  ▼                  ▼
     └────(sleep)──── [SLEEP] <------ [done]
```

- `IDLE`：等定时器（或低功耗 tickless 唤醒）。
- `MEASURE`：调 `sensor_task` 取数，成功进 `REPORT`，失败重试 3 次回 `IDLE`。
- `REPORT`：组帧发送，等待 ACK（或超时），进 `SLEEP`。
- `SLEEP`：进 STOP 模式，由 RTC/定时器唤醒回 `IDLE`。

## 4.5 低功耗：tickless idle 与 STOP 模式

要达成第一章算出的 14 μA 级平均电流，必须让 MCU 在空闲时睡下去：

1. **FreeRTOS 开启 `configUSE_TICKLESS_IDLE`**，空闲时停掉 SysTick，不再周期性唤醒。
2. **STOP 模式**：调用 `HAL_PWR_EnterSTOPMode`，内核停摆、外设时钟关，仅 RTC/外部中断可唤醒。
3. **唤醒源**：RTC 闹钟（周期唤醒采集）、按键（配网）、蓝牙模块中断（收到手机指令）。

> 注意：STOP 模式下主时钟停了，唤醒后要**重新配置系统时钟（HSI/HSE + PLL）**，否则 UART/I2C 波特率全错。这是最容易遗漏的一步。

## 4.6 优先级设计反模式

| 反模式 | 现象 | 修正 |
| --- | --- | --- |
| 所有任务同优先级 | 顺序轮转，无实时性 | 按"晚一点就出错"的程度排优先级 |
| 高优先级死循环 | 低优先级饿死 | 高优先级必须主动阻塞（延时/等队列） |
| 在 ISR 里做重活 | 关中断时间过长 | ISR 只给信号量，搬数据交给任务 |
| 队列无限阻塞 | 内存撑爆 | 设合理队列长度与超时 |

## 4.7 内存与栈

- 每个任务独立栈，大小按**最坏调用深度 + 中断嵌套**估，再用 `uxTaskGetStackHighWaterMark` 反测余量。
- 总堆来自 `FreeRTOSConfig.h` 的 `configTOTAL_HEAP_SIZE`，要留足四个任务 TCB + 栈 + 队列。
- 项目级总内存 = RTOS 堆 + 静态区（bss/data）+ 中断栈。溢出会静默崩溃，必须测水位。

## 本章要点

- 任务拆分：sensor / report / battery / led，各司其职
- 队列传数据、信号量通知事件，发送方与接收方解耦
- 状态机收敛行为：IDLE→MEASURE→REPORT→SLEEP
- 低功耗靠 tickless idle + STOP，唤醒后重配时钟
- 优先级反模式：别全同优先、别高优先死循环、ISR 别搬数据
- 用栈水位线反测每个任务的真实栈用量
