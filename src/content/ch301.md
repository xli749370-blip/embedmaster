# 第一章 从点亮一颗 LED 开始：工程结构与 GPIO

> 大多数人学单片机的第一个动作是点灯。但同样是点灯，有人三天后就撞上"为什么我的 IO 一接电机就复位"，有人已经知道问题出在灌电流上限。差别不在会不会写 `HAL_GPIO_WritePin`，而在于是否理解这行代码背后经过了哪些层。

## 1.1 上电之后，芯片到底做了什么

按下复位键或者插上电的瞬间，CPU 并不是从 `main` 开始执行的。它做了一连串固定动作，理解这段流程能解释掉后面 80% 的"玄学问题"。

上电顺序大致是：

1. **从 0x0000_0000 取出栈顶地址**，写进 MSP（主栈指针）。这个地址是链接脚本决定的，不是你写的。
2. **从 0x0000_0004 取出复位向量**，跳过去执行 `Reset_Handler`。
3. `Reset_Handler` 里做三件事：调用 `SystemInit` 配置时钟、把 `.data` 段从 Flash 拷贝到 RAM、把 `.bss` 段清零，最后 `bl main`。
4. 这才进入你的 `main()`。

由此可以推出两个很实用的结论：

- **全局变量在 `main` 之前就已经初始化好了**，靠的是 `.data` 段拷贝。但如果你在 `SystemInit` 里就用了全局变量，它可能还是垃圾值。
- **栈大小是在启动文件里写死的**（通常是 `Stack_Size EQU 0x400`，即 1KB）。局部大数组会直接踩坏栈，表现是进 `HardFault_Handler` 或者随机跑飞。

> 遇到"程序下载进去就死机、单步却正常"的情况，第一件事查栈溢出，第二件事查时钟配置。这两条占了新手 hardfault 的一大半。

## 1.2 一个 HAL 工程由哪些文件构成

CubeMX 生成的工程看起来文件很多，真正需要你关心的只有几类：

| 文件 / 目录 | 作用 | 要不要改 |
|---|---|---|
| `Core/Src/main.c` | 你的业务代码主战场 | 改 |
| `Core/Src/stm32f1xx_it.c` | 所有中断服务函数 | 改 |
| `Core/Src/stm32f1xx_hal_msp.c` | 外设底层初始化（时钟、引脚复用） | 少改 |
| `Core/Inc/main.h` | 引脚宏定义 | 改 |
| `Drivers/STM32F1xx_HAL_Driver/` | ST 官方 HAL 库 | 不改 |
| `startup_stm32f103xb.s` | 启动文件，定义向量表与栈大小 | 极少改 |
| `STM32F103C8Tx_FLASH.ld` | 链接脚本，定义内存布局 | 极少改 |
| `system_stm32f1xx.c` | `SystemInit` 时钟初始化 | 不改 |

**一个关键分界：`main.c` 里 CubeMX 用 `/* USER CODE BEGIN */ ... /* USER CODE END */` 包住的区域，是重新生成代码时不会被覆盖的。** 所有自己的代码都必须写在这两个标记之间，否则下次点"Generate Code"就全没了。这是新手最常见的血泪教训。

## 1.3 GPIO 的八种工作模式

STM32F1 的每个 GPIO 引脚可以配置成 8 种模式。这不是可选项的堆砌，每种模式对应明确的电路含义。

| 模式 | 等效电路 | 典型用途 |
|---|---|---|
| 输入浮空 | 高阻，无上下拉 | 外部已有上下拉时 |
| 输入上拉 | 内部 30–50kΩ 接 VDD | 按键接地、悬空信号 |
| 输入下拉 | 内部 30–50kΩ 接 GND | 按键接 VDD、默认低 |
| 模拟输入 | 断开数字缓冲器 | ADC 采样、低功耗 |
| 推挽输出 | 上管拉高、下管拉低 | LED、驱动能力要求高 |
| 开漏输出 | 只有下管，上拉靠外部 | I2C、电平转换、线与 |
| 复用推挽 | 由外设接管，推挽 | UART TX、SPI、PWM |
| 复用开漏 | 由外设接管，开漏 | I2C 的 SCL/SDA |

**推挽和开漏的区别，是必须真正理解的一条。** 推挽输出能主动输出高电平和低电平，驱动能力强；开漏输出只能主动拉低，输出高电平时是靠外部上拉电阻"被动"拉起来的。开漏的价值在于可以多器件并联在一条线上而不会短路——I2C 就是靠这个特性工作的，如果误配成推挽，两个器件一个想拉高一个想拉低，就是电源直接对地，烧引脚。

配置成复用模式时，引脚的控制权从 GPIO 外设移交给定时器、串口等外设。**如果你配了 PWM 但引脚还是普通推挽输出，波形是出不来的**——这是新手配 PWM 失败的第一原因。

```c
/* 推挽输出点亮 LED 的标准配置 */
GPIO_InitTypeDef g = {0};
g.Pin   = GPIO_PIN_13;
g.Mode  = GPIO_MODE_OUTPUT_PP;   /* 推挽输出 */
g.Pull  = GPIO_NOPULL;
g.Speed = GPIO_SPEED_FREQ_LOW;   /* 2MHz 足够点灯 */
HAL_GPIO_Init(GPIOC, &g);
```

输出速度这一项容易被忽略。它指的不是"代码跑多快"，而是**引脚电平翻转的上升/下降沿斜率**。速度越高，边沿越陡，EMI 辐射越强。点灯、按键这种低速场合用 `LOW` 就够，只有 SPI 高速通信、PWM 高频输出才需要 `HIGH`。速度配高了不会更好，只会让板子更难通过 EMC。

## 1.4 点亮 LED：从寄存器到 HAL

### 限流电阻不能省

LED 是电流驱动器件，不是电压驱动。直接接 3.3V 会瞬间烧掉，因为它的正向压降几乎是固定的（红光约 1.8–2.0V，蓝/白约 3.0–3.3V），多余的电压全部落在内阻极小的 PN 结上。

限流电阻按下式计算：

$$
R = \frac{V_{CC} - V_f}{I}
$$

举例：3.3V 供电、红色 LED（$V_f = 1.9V$）、目标电流 5mA：

$$
R = \frac{3.3 - 1.9}{0.005} = 280\ \Omega
$$

取标称值 330Ω，实际电流约 4.2mA，亮度足够。

**为什么是 5mA 而不是 20mA？** 因为 STM32 单个 IO 的绝对最大灌/拉电流是 25mA（部分型号 20mA），但整颗芯片所有 IO 加起来也有总限额，且长期跑在极限会缩短寿命、增加发热。工程上的经验值是：**单个 IO 长期不超过 8mA，总和不查手册不要超过 100mA**。

### 高电平点亮 vs 低电平点亮

两种接法都常见，选哪种有讲究：

| 接法 | 电流方向 | 逻辑 | 上电瞬间状态 | 适用 |
|---|---|---|---|---|
| IO → 电阻 → LED → GND | IO 向外拉电流（source） | 写 1 亮 | IO 默认为浮空输入，**LED 不亮** | 通用 |
| VCC → 电阻 → LED → IO | IO 向内灌电流（sink） | 写 0 亮 | IO 默认为浮空，**LED 不亮** | 驱动能力要求高 |

**灌电流（sink）的驱动能力通常比拉电流强**，因为 NMOS 下管的导通电阻比 PMOS 上管小。所以驱动大电流负载时优先用低电平有效的接法。

如果你希望上电默认就点亮（比如电源指示灯），需要在代码里尽早初始化，或者干脆用硬件接法实现——但要注意不要和调试口复用同一引脚。

### 三种点灯写法

```c
/* 写法一：直接操作寄存器，最快，可读性最差 */
GPIOC->BSRR = GPIO_BSRR_BS13;   /* 置位，点亮 */
GPIOC->BSRR = GPIO_BSRR_BR13;   /* 复位，熄灭 */

/* 写法二：标准外设库（SPL）风格，F1 老工程常见 */
GPIO_SetBits(GPIOC, GPIO_Pin_13);

/* 写法三：HAL 库，本项目采用 */
HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);
HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
```

`BSRR` 寄存器值得单独说一句：它是"置位/复位寄存器"，写 1 有效、写 0 无动作，而且是原子的。对比 `ODR` 寄存器需要"读-改-写"，在多任务或中断环境下可能被中断打断导致竞态。**所以需要原子翻转时用 BSRR，不要用 ODR。**

## 1.5 按键输入：抖动是物理事实

机械按键的金属触点闭合瞬间会弹跳，产生 5–20ms 的连续通断。如果直接在中断里读，按一次会被识别成十几次。

实测波形大致是这样：按下瞬间电平在 0/1 之间无规律跳变，稳定时间取决于按键质量，便宜的轻触按键能抖 20ms。

### 方案一：延时消抖（最常见，但有代价）

```c
if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
    HAL_Delay(20);                                  /* 阻塞 20ms */
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
        /* 确认按下 */
    }
}
```

问题在于 `HAL_Delay` 是**阻塞**的，这 20ms 里 CPU 什么都不能干。在一个实时性要求高的系统里（比如你的无人机需要 500Hz 的姿态环），这种写法是不可接受的。

### 方案二：定时器轮询 + 状态机（工程推荐）

让一个 10ms 周期的定时器中断去采样按键，连续两次读到相同电平才认账：

```c
/* 每 10ms 由定时器中断调用一次 */
void Key_Scan(void)
{
    static uint8_t cnt = 0;
    static uint8_t last = 1;
    uint8_t now = HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0);

    if (now != last) {
        if (++cnt >= 2) {          /* 连续 2 次（20ms）一致才更新 */
            last = now;
            cnt  = 0;
            if (now == 0) Key_OnPress();   /* 下降沿：按下 */
        }
    } else {
        cnt = 0;
    }
}
```

这个写法不阻塞、能识别长按短按、且抖动容忍度可调（改 `cnt` 阈值即可）。代价是需要占用一个定时器。

### 上拉电阻的取值

内部上拉约 30–50kΩ，配上按键和 PCB 走线电容，RC 时间常数在微秒级，对消抖影响可以忽略。**但如果导线很长（超过 20cm）或者环境干扰强，内部上拉太弱，应改用外部 4.7kΩ–10kΩ 上拉**。否则空闲时引脚电平会被干扰拉低，产生虚假触发。

## 1.6 六个高频踩坑

**坑一：忘记使能 GPIO 时钟。**
`HAL_GPIO_Init` 之前必须 `__HAL_RCC_GPIOA_CLK_ENABLE()`。CubeMX 生成代码时会自动加，但手写代码时极易遗漏。表现是配置全部正确、代码逻辑无误、引脚就是不动。

**坑二：引脚被调试口占用。**
PA13/PA14 是 SWDIO/SWCLK，PA15/PB3/PB4 默认是 JTAG 引脚。如果把它们配成普通 GPIO，会直接导致下载器连不上，只能靠"按住复位键再点下载"救回来。正确做法是先调用 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 关闭 JTAG 保留 SWD。

**坑三：驱动感性负载不加减速二极管。**
直接 IO 驱动继电器、小电机，断电瞬间线圈产生反向电动势（可达几十伏），会把 IO 打穿。必须加续流二极管（如 1N4148）并在 IO 与基极间串限流电阻，或者干脆用 MOS/三极管隔离。

**坑四：把大电流负载直接挂 IO。**
舵机、直流电机、WS2812 灯带（一颗满亮 60mA）都不能直接由 IO 供电。IO 只是给信号，供电要走独立电源并共地。

**坑五：开漏输出忘记接上拉。**
配了开漏却没接外部上拉，引脚永远输出不了高电平。测出来一直是 0V，会误以为是芯片坏了。

**坑六：初始化顺序错。**
先配引脚再开时钟，或者先开外设时钟再配引脚复用，都可能失败。正确顺序是：**开 GPIO 时钟 → 配置引脚模式 → 开外设时钟 → 配置外设 → 使能外设**。

## 1.7 本章小结

这一章其实只讲了一个核心思想：**每个引脚背后都是一片硅片上的具体电路，配置项不是勾选框，而是电路开关。**

- 上电后从向量表启动，`main` 之前全局变量已初始化，栈大小在启动文件里写死。
- 自己的代码必须写在 `USER CODE BEGIN/END` 之间。
- 推挽 vs 开漏，本质是"能否主动输出高电平"；I2C 必须开漏。
- LED 必须限流，单 IO 长期电流控制在 8mA 以内。
- 消抖的本质是等待机械稳定，方案一是阻塞延时，方案二是定时采样状态机。
- 六类高频故障：时钟没开、引脚被占用、感性负载反压、大电流直挂、开漏无上拉、初始化顺序错。
