# 第六章 位操作的艺术：RMW、位带与内存屏障

[[anim:bit-band]]

`GPIOA->ODR |= (1 << 3);` 这行代码你写过几百次。它编译成几条指令？中间态是否可能被中断打断？有没有一种方式"一次写、只写那一位"？这一章把最基础的位读写拆到指令级：读改写（RMW）的竞态窗口、位带别名区的地址魔法、volatile 究竟承诺了什么、以及编译器如何在你不知情时"优化"掉你以为存在的时序。

## 6.1 RMW：一条"或等"背后的三条指令

`ODR |= (1 << 3)` 不是原子操作，展开是三步：

```text
LDR   r0, [r1]      ; ① 读整个 ODR（32 位）
ORR   r0, r0, #8    ; ② 仅置起 bit3
STR   r0, [r1]      ; ③ 把 32 位整体写回
```

竞态窗口在 ① 和 ③ 之间。设想主循环把 PA3 置 1，而 ISR 要把 PA7 置 1：

```text
主循环  LDR   r0, [ODR]        ; 读到 0x00
--- 此刻 EXTI 中断打断 ---
ISR     LDR   r0, [ODR]        ; 读到 0x00
        ORR   r0, #0x80        ; 得 0x80
        STR   r0, [ODR]        ; 写回 0x80 → PA7 = 1
--- 中断返回 ---
主循环  ORR   r0, #0x08        ; r0 还是旧的 0x00 → 0x08
        STR   r0, [ODR]        ; 写回 0x08 → PA7 又变回 0 ！
```

ISR 的修改被主循环的"旧值写回"抹掉了。这不是理论风险——**任何在 ISR 和主循环里操作同一个"可 RMW 寄存器"的场景都可能发生**，比如两处都往 `RCC->APB2ENR` 开不同的外设时钟。

三层防护（由轻到重）：

1. **临界区**：`__disable_irq()` / `__enable_irq()` 包住 RMW，代价是拉高中断延迟；
2. **职责单一**：同一个寄存器只在一处修改（时钟使能全放 `clock_init()`）；
3. **位带**：硬件把"改一位"变成"写一个字"，天生原子——见下一节。

$$\text{竞态条件} = \text{RMW 窗口} \cap \text{并发修改} \ne \varnothing$$

## 6.2 位带：把"一位"映射成一个地址

Cortex-M3/M4 在两个区域提供位带（Bit-Band）支持：SRAM 的最低 1 MB（`0x2000_0000 ~ 0x200F_FFFF`）和外设区的最低 1 MB（`0x4000_0000 ~ 0x400F_FFFF`）。配套各一张**别名区**，每 1 个 bit 膨胀成 32 位字：

$$\text{alias} = \text{base} + (addr - \text{region}) \times 32 + bit \times 4$$

以 `GPIOA->ODR`（0x4001_0C0C）的 bit3 为例：

```text
alias = 0x4200_0000 + (0x4001_0C0C - 0x4000_0000) × 32 + 3 × 4
      = 0x4200_0000 + 0x2_1840 + 0xC
      = 0x4202_184C
```

对 `*(volatile uint32_t*)0x4202_184C = 1;` 写一个字，硬件只改 ODR 的 bit3——**一次写、无 RMW、天然原子**。读这个地址返回 0 或 1。

HAL 底层的 `__HAL_RCC_GPIOA_CLK_ENABLE()` 用的是另一种等效手段（RMW + 关中断保护，因为 F103 的 RCC 不在位带区）；而 `GPIO_BSRR` 是更常用的"硬件原子置位/清零"寄存器——**优先用 BSRR，位带用在 BSPRR 覆盖不到的寄存器上**（如 `EXTI->IMR`、`NVIC->ISER` 不在位带区的例外要逐个核对地址手册）。

## 6.3 volatile：一条承诺与两条不承诺

`volatile` 是和编译器的一纸合同，只承诺两件事：

1. **每次访问都真实发生**：不合并、不删除、不缓存到寄存器（否则 `while(!(ADC->ISR & 4));` 会被优化成读一次的死循环）；
2. **访问顺序不与其他 volatile 访问交换**。

它**不承诺**的是：

- **原子性**：`volatile uint32_t x; x++;` 照样是三条指令、照样有 RMW 竞态；
- **CPU 与外设之间的顺序**：CPU 流水线和写缓冲可能重排对普通内存的访问——这就是内存屏障存在的理由。

所以标准答案要背下来：**volatile 解决"编译器优化"，屏障解决"CPU 重排"，原子指令/RMW 防护解决"并发"——三个问题三把钥匙，互相不可替代**。

## 6.4 内存屏障：DMB / DSB / ISB

Cortex-M 提供三条屏障指令：

- **DMB**（Data Memory Barrier）：保证屏障前的内存访问在屏障后的内存访问之前完成；
- **DSB**（Data Sync Barrier）：更彻底——等**所有**内存访问彻底完成才放行后续指令；
- **ISB**（Instruction Sync Barrier）：刷流水线，让之后的取指看到最新状态。

什么时候真的需要：

```c
/* 场景：改 VTOR 之后立刻有中断可能到来 */
SCB->VTOR = 0x08003000;
__DSB();          /* 确保 VTOR 写入到达寄存器 */
__ISB();          /* 确保后续取指走新向量表 */

/* 场景：自修改代码 / 关中断进入临界区前的访问保序 */
```

CMSIS 已封装好：`__DSB()`、`__ISB()`。HAL 的 `HAL_NVIC_SystemReset()` 末尾那句就是经典组合——**先 DSB 等所有写落地，再 ISB，保证复位指令不被流水线提前吞掉**。

## 6.5 编译器优化下的时序陷阱

写延时循环最典型的翻车现场：

```c
uint32_t d = 100000;
while (d--) ;              /* -O2：整个循环被删除！d 没被外部使用 */
```

修复方式不是 `volatile`（`volatile uint32_t d` 也能让循环保留，但每次读写都进栈，效率低），而是**用硬件资源**：`__NOP()` 循环、DWT->CYCCNT 计数、或干脆用定时器。**"软件延时"的正确性永远不该依赖编译器的手下留情**。

另一个隐蔽陷阱：连续两次写同一外设寄存器，编译器若判断"第二次覆盖第一次"，可能合并成一次——除非寄存器声明带 volatile（HAL 全带）。但**两个不同寄存器之间的顺序**，volatile 不保护，需要 DMB——比如配置 DMA 前先写好缓冲区再启动 DMA，中间最好隔一道屏障（很多 HAL 例程省略是因为写 DMA 寄存器本身有等待位兜底）。

## 6.6 五个经典坑

1. **以为 volatile = 原子**：`volatile int count; count++;` 在 ISR 与主循环间照样丢计数。要原子就关中断或用 `__atomic` 内建。
2. **在位带不覆盖的地址上硬算别名**：区域外地址算出的 alias 无效，写入静默丢失。先查手册确认寄存器在位带区内。
3. **RMW 竞态只修一处**：两个文件都在 RMW 同一个寄存器，只在一处加临界区没用，要按"寄存器"统一治理。
4. **屏障滥加**：每行寄存器写后都插 DSB，白白丢性能。只在**顺序敏感点**（VTOR、复位、DMA 启动、自修改代码）加。
5. **软件延时依赖 -O0**：开发时正常、开 -O2 后延时不生效导致外设初始化过快失败。延时速改硬件实现。

## 6.7 本章小结

- `|=` 是**三条指令的 RMW**，窗口期内被 ISR 打断会丢别人的修改——三把钥匙：**临界区、职责单一、位带/BSRR**。
- 位带别名公式：**base + (addr − region)×32 + bit×4**，一次写一字 = 原子改一位。
- **volatile 管编译器，屏障管 CPU，原子手段管并发**——三件事别混。
- 屏障三兄弟：**DMB 保序、DSB 等完成、ISB 刷流水线**；敏感点在 VTOR、复位、DMA 启动。
- 软件延时循环会被 -O2 整段删除，**延时的正确性不靠编译器**。
